# ADR-011 技术设计收敛

本轮继续 PREPARE，基线 b511ebb。设计选择与后续运行能力分开；没有启动 V021，实现准入仍缺，V020保持IN_PROGRESS。原提案和原准备结果不改写。正式状态读取机器登记与本轮非模板 ADR_DECISION。

## 六项选择

| 原未决项 | 本轮选定 | 仍受阻的后续动作 |
|---|---|---|
| 无变化章 | 独立抽取观察可零提议；None/0仅表示未产生可编码操作，不是整章无变化。原非空Delta/Candidate/Canon不变 | 零Delta进入既有章节提交明确拒绝；未来版本兼容另作决定 |
| 有限支持范围 | 发现/物化/preview分层，未知叙述或操作不静默丢弃，同fact多次转移不做净值合并 | 未支持内容的语义与生产提交继续UNKNOWN/阻断 |
| 证据与覆盖复查 | 原文盲发现两职责：提议与先封存的独立命题清单；仅共享raw/身份类型别名/语法/坐标，不共享答案或分类AST | 工程有限profile不等于自然全文正确率；无合格依据不能生产PASS |
| 生产授权来源 | 受控管理grant+可信入口actor，checker/裁决/issuer分责，权限版本保守失效；不透明许可引用读取真实持久记录 | 当前仍无P7生产issuer/真实部署授权，不靠TEST配置改标签 |
| Permit生命周期 | 显式版本政策max_lifetime、服务端issued_at与expires_at；缺参数/过期/版本失效拒绝，无默认TTL | 数值/名单/部署/取消竞争/恢复测试在V026启用前冻结和验证 |
| 任务准入 | 设计接受不改任务/依赖/G-P5，不继承V020例外 | V021仍OPEN/PLANNED，IMPLEMENT/LIVE_CALL/CERTIFY仍不能执行 |

选择依据是现行03/05规范、ADR004/005/006与实际源契约；详见主ADR及原SOURCE_INVENTORY。未调用模型、未执行抽取或提交业务测试。

## 纸面正反例走查

以下为设计走查，结果列是未来实现必须满足的行为；不是已执行测试、语义正确率或AT021完成证据。

| 情况 | 选定设计必须给出的结果 |
|---|---|
| 原始全文、身份/版本/哈希完整，实际有限方法执行后0提议 | 保留零提议观察和完整结果/覆盖；不造Delta/Candidate，不授提交资格 |
| 前半静态、后半未支持事件，0提议 | 保留尾段未支持与UNKNOWN，不能报整章无变化 |
| 错hash/source/span/quote或未执行 | 明确绑定/执行失败或错误诊断，不降为零提议成功 |
| 同fact A→B→A或多次变化 | 保留过程；有限语言不支持则UNKNOWN，不取净值/最后值掩盖 |
| 同一句引文出现两次，一次传闻/否定，一次实际发生 | 原文精确位置和完整限定词分开核对，不find首匹配/截词冒充证据；否定转移不能推出旧值仍成立 |
| 回忆过去事件/计划未来事件 | 不当成本章新发生事实；无法确认时UNKNOWN |
| proposer漏掉正文尾段、inventory只看proposal | 不是独立复查，不能得到语义合格结论 |
| backend获知gold Delta/遗漏位置/Contract.required预期结果 | 答案泄漏；只能说明诊断器或映射校验，不能算自动发现 |
| 全字符分段完整、抽取和inventory均自报高置信度 | 只证明结构材料存在，不自动得到生产语义PASS |
| 人工“同意”但缺grant/候选错绑/确定硬失败 | 拒绝有效裁决或Permit；不覆盖硬失败 |
| issuer撤权或政策/执行版本改变后旧记录尚未提交 | 旧证据/Permit失效，签发与提交再次核验当前真实版本 |
| 缺TTL政策参数、未知时间或已过期 | 无默认回退，签发/消费拒绝 |
| 已成功提交后到期/撤权或响应丢失 | 同request/载荷恢复原收据，核身份scope；不重写或声称撤销既成提交 |
| 已接受ADR但V020未关闭/G-P5未验证/V021仍OPEN | 仅设计已定，实施入口继续BLOCKED |

## 实施前置交接

下一代码工作应一次覆盖“当前完整assembly → 独立观察/实际有限提议 → 精确原文和盲inventory → 覆盖/未知诊断与可恢复结果”，使用同一Workflow服务，不继续无限追加V020切片。未来实现需有V021自己的明确准入和固定scope/review；本文件不是准入grant。

预期实际范围为V021抽取模块/专项测试与必要的现有Workflow薄适配、持久观察消费；不引入生产CheckExecution、Q0–Q3、正式Permit/Canon提交或新Provider派发。精确代码/存储边界在该任务开工包冻结，本轮没有创建任何源接口、Schema或业务测试。

当前可以完成技术ADR的复核/正式记录；未来能力必须用各任务真实代码与执行证据证明，不能让“尚未实现P7”成为重复写ADR的循环前提，也不能据本设计绕过实施门禁。
