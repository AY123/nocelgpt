# 五、首先解决 ADR-001

V2-001 要求：

`ADR-001 — 精确运行环境与锁定工具`

所以在进入 IMPLEMENT 之前，必须完成 ADR-001。

根据当前项目规范和实际环境，对以下内容做最小必要决策：

* Python 精确版本策略
* uv 版本/锁定策略
* PostgreSQL 镜像与版本策略
* dependency lock policy
* 本地开发环境和 CI 环境一致性原则

1. 不追求“永远最新”。

5. 不允许用 SQLite 替代 PostgreSQL 的关键语义测试。
6. 不引入当前没有消费者的复杂基础设施。

ADR-001 必须形成正式 ACCEPTED decision record，并符合现有 ADR / Evidence 治理要求。

如果 ADR-001 尚未满足进入 IMPLEMENT 的条件，则停在 PREPARE，不得偷偷开始实现。

# 十四、状态管理

任务状态必须遵循：

```text
OPEN
→ IN_PROGRESS
→ IMPLEMENTED
→ VERIFIED
→ CLOSED
```

禁止直接：

```text
OPEN → CLOSED
```

含义：

* `IN_PROGRESS`：正式实施开始
* `IMPLEMENTED`：代码/配置存在
* `VERIFIED`：真实适用测试与 CI 证据成立
* `CLOSED`：验收记录、Finding disposition 等全部满足

特别注意：

当前 P0 尚未建立完整可信远端 CI。

因此：

> 如果 V2-001 的 CLOSED 条件要求尚未建立的 V2-004 真实 CI Evidence，则不要假装 CLOSED。

允许：

```text
IMPLEMENTED
```

或规范允许的中间状态，

然后等待 V2-004 建立真实 CI 后完成最终 closure。

状态必须严格依据当前 machine policy。
