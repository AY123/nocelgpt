# 平台、隔离、安全与交付

## 1. 依赖和运行环境

P0 创建实际工程和 uv.lock，记录 Python、数据库、工具版本和镜像摘要。干净环境使用锁定安装；禁止偷偷更新依赖以让 CI 通过。更新要有差异、检查及回归。

业务源码使用 `src/anovel`，测试和归档分开。归档 Schema/示例代码不自动被打包、导入、扫描为现行生产合约。正确处理 Python/测试 discovery 路径，避免两个 Canon 实现被装入。

## 2. 阶段性 CI

阶段规则以 [ci-gates.yaml](machine/ci-gates.yaml) 为准。P0 开始实际启用静态、单元、资料/Schema、架构、密钥/依赖与 PostgreSQL 基础环境检查。CAS/幂等/重建随 P2 代码启用；完整确定性闭环在 P7；认证 smoke 在 P8。

适用硬门禁 `allow_failure: false`。当前六门对每个交付代码版本适用，本地检查后仅在关键交付手动触发远程 CI；不要求每次 push 自动运行，CI 缺失不能声称该版本已获远程验证。未来未启用项有 phase 和理由，不能显示已通过。档案中的已知缺陷作为回归输入，不用排除已启用测试或允许失败制造绿色。

AI 开发受 [AI 开发执行协议](AI_EXECUTION_PROTOCOL.md)约束。P0 接入实际差异检查，核对任务范围、验收弱化、测试跳过与扫描排除变化；比较基线不能由同次候选改动自行替换。合法规则修订保留依据和替代验证，不将“改后内部一致”当成没有降低要求。

live Provider 可 scheduled/protected manual/release 运行；首次真实模型接缝、认证及有关发布节点必须取得新鲜证据。缺密钥、预算或 Provider 能力为未完成/阻断，不默认成功。

## 3. Secret 与依赖门禁

密钥只经本地未跟踪配置或受控环境注入；示例使用明确无效占位值；日志不输出真实凭证。扫描当前文件及实际项目历史时不将命中值复制进报告。发现真实泄露按事故处置，删除文本不等于完成轮换。

依赖检查记录数据库/工具版本、策略和适用例外。任何例外必须具体、有期限和责任，不能使用全局 allow_failure。P0 用无害测试夹具验证扫描能阻断，避免引入真实密钥作为测试数据。

## 4. 作用域和权限

project/branch 贯穿数据约束、查询、缓存、检索、blob key、工作流和 UI/报告。允许全局只读 Genre 目录，但不能把别的项目 Canon 当共享信息。人类管理操作也有作用域和审计。

仅导入检查不足以防旁路：在接口、数据库事务、授权和隔离测试中同时验证。特权连接不能暴露给 Writer、Reviewer 或 Reference Worker。

开发执行权限与小说运行权限分别管理。当前项目按用户确认的 internal_single_operator 模式运行：Owner 同时控制实现与规则，GitHub 分支保护、独立角色负控及专用 protected runner 不作为 V2-004 退出条件；不声称已建立对抗性隔离。六门硬失败、真实远程结果核对、精确且有限期的 Owner 安全决定继续强制。多人写入或自动发布前重新评估权限边界。此变更不降低未来小说运行时的数据/Canon 权限要求，依据和原要求见 changes/2026-10-16_V2-004_SINGLE_OPERATOR_CLOSURE.md。

## 5. 运行追踪与成本

从 P5 首次模型调用开始保留 run/logical request/attempt、输入输出 hash、模型和政策、check、repair、permit、commit receipt 血缘。未知费用独立记账，不能记为零。指标同时呈现总尝试与成功数。

健康检查必须反映依赖可用性，不能对失败一律返回成功。监控不需要 P0 建完整平台；先有结构化日志和最小可诊断结果。

## 6. 恢复与发布

P2 验证事件/投影重建和事务边界；P8 验证工作流故障恢复；V2-058 在 P12 集成正式备份/恢复验收，不意味着早期持久状态可以没有恢复策略。

ADR-006/V2-009 定义早期恢复边界，V2-028 在首次认证汇总前执行最小隔离恢复，核验数据库与不可重建 Artifact 的闭包；不能用同库投影重建代替数据库丢失后的恢复。正式自动化和长期演练仍由 V2-058 承接。

V2-004 核验实际远端流水线和被测代码提交；单人模式明确记录适用保护的未启用及接受范围，不把它伪称为保护验证通过。GitLab 历史设置或403仅作历史输入，不能推断当前GitHub设置。缺少访问或原始结果时相应来源仍未验证。

V2-059 建立正式 release manifest；更早运行仍记录代码、锁文件与模型/规范指纹。发布成功、备份成功和章节接受成功须各有独立证据。

## 7. 当前提交证据与历史资料整理

V2-004 的 CI 在被测提交 checkout 后生成独立 artifact，保留运行身份、命令、退出状态、原始日志和内容 hash。核对项目与 commit/pipeline/job 归属、真实结果及产物可读性；失败、取消、未知结果同样保留。当前提交未运行、API 无权访问或产物缺失时，不用已提交的历史 PASS 补位。具体 CI 接入由 V2-004 实施，本次资料修订不配置远端或发布 Release。

P0 将正式动作前置检查接入执行命令及 CI，切换动作时重查执行包、输入版本、适用阶段/依赖与 ADR；实际副作用不能只依靠 AI 自填动作名称限制。本地执行包校验不代替动作拦截器、远端来源认证或平台权限。操作者可在既定范围自主推进，未知授权、越界或证据失效时停止对应动作并记录原因。

V2-001 输出 `docs/repository-layout-migration.md`，逐项列出根历史目录/ZIP、对应 archive 快照、hash/独有版本、引用、保留与迁移方案。来源登记中的 origin 是追溯定位，不代表根副本可直接删除；须核对实际覆盖与链接，保留可恢复副本及未归档资料。P0 入场不以搬空根目录为条件。

清单显式覆盖隐藏工具目录中的历史资料，优先核对 `.claude/convergence/` 的文件集合、逐文件 hash、实际入口/配置引用与潜在误读面。工具配置、规则入口和历史研究分开记录；没有自动加载证据就标“未发现实际消费者”，不写成已证实事故。归档一致只是迁移条件之一，不能直接推导可删除；迁移后还需核对现行入口和引用。不能把工具配置整体搬走或为目录整洁改动运行权限。

新生成的下载包可放 `dist/planning/` 等已忽略的交付目录；正式工程中可由 CI artifact 或经授权的 Release 承载。既有根目录 ZIP 不自动删除，也不默认上传。构建和测试发现规则显式区分生产代码、历史 archive 和分发产物，避免靠搬删文档解决扫描边界。
