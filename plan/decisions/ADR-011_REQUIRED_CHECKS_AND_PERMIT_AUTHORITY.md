# ADR-011 — 必跑检查、语义证据与生产 Permit 权限

设计版本：1.0；2026-11-18技术复核。责任：quality-maintainer。关联 V2-021～026、V2-029；最晚时点为 V2-021 的 before_interface_implementation。生效状态以机器登记及其非模板 ADR_DECISION 为准；设计接受不是接口实现、任务准入或运行放行。

用户继续 ADR-011／V2-021 PREPARE。本轮完成技术设计决定，不授予 V021 实施准入；V2-020 保持 IN_PROGRESS。准备依据见[执行包](../validation/execution/V2-021/execution-packet.yaml)和[本轮设计收敛](../validation/execution/V2-021/design-resolution-20261118/DESIGN_RESOLUTION.md)。初始提案和当时REQUIRED状态保留在原准备记录/Git历史，不作当前状态源。当前唯一已交付的本地接缝到 LOCAL_DRAFT_HANDOFF，随后停止在整章抽取未实现；不因本文出现检查或 Permit 字段而改变该停点。

## 1. 触发与既有约束

正文后半章存在非法能力，抽取器却只列出前半章合法变化时，合法 Delta 不能证明整章合格。“甲听说乙破产”也不能直接变成乙已破产的 Canon 事实。模型置信度、空 Findings、人工“喜欢这稿”、正确 hash 均不能单独解决这些问题。

遵循[03 契约](../03_DOMAIN_CANON_AND_ARTIFACT_CONTRACTS.md)、[05 质量规范](../05_PRODUCTION_CONTEXT_QUALITY_REPAIR.md)及已接受的 [ADR-004](ADR-004_DELTA_OPERATION_CONTRACT.md)、[ADR-005](ADR-005_CANONICAL_BYTES.md)、[ADR-006](ADR-006_PERSISTENCE_BOUNDARY.md)：有限变化语言、原始字节身份、唯一提交服务、同事务内执行版本/取消/撤权次序不变。没有扩大 Delta 操作、改变 Canon 写路径或接受测试 Permit 的决定。

实际代码边界：NarrativeDelta 仅为有限结构候选，ProseEvidence 尚无全文 hash/精确 span；ChapterCandidate 要求 Delta.source_id 等于章节候选 ID，不能直接塞入 source_id 为场景 ID 的旧映射。ChapterAssembly 保存完整原文及分段，但整章 Delta 尚未抽取。当前没有生产 CheckExecution，现有 ProtectedPermitIssuer 仅隔离 TEST。

## 2. 选定方案

选定“有限确定性验证＋明确语义证据＋有范围的授权裁决”。区分四类产物，不共享一个可自报放行的 status：

| 产物 | 产生与核验职责 | 不授予的能力 |
|---|---|---|
| 抽取提议与覆盖材料 | V2-021 消费当前完整候选，列出有限变化、叙述分类、精确证据和遗漏/未知 | 不是 Q0–Q3 PASS，不是 ChangeSet/Permit |
| CheckExecution | V2-022 定义执行记录/完整性，V2-023～025 实现对应命题检查 | 模型不能自报已被可信 checker 执行 |
| 授权语义裁决 | P7 在有限命题内记录真实操作者、依据及授权范围 | 创作同意不能覆盖硬失败或签发 Permit |
| 生产 Permit | V2-026 核验完整证据闭包，唯一 Canon 服务提交时重验 | 不复用 P2 TEST 身份，不授权发布 |

CLI、任务和未来 UI 消费同一 Workflow 服务。后续代码只在相应任务准入与 ADR 接受后实现，不在准备期创建第二编排服务或占位接口。

## 3. 每项检查的冻结契约

必跑集合来自版本化的受信任政策及冻结 Contract/Pack，不能接受 caller 自选 required-check 列表、ALLOW、PASS 或 skip。每个检查契约至少明确：

1. 稳定 check ID、版本、命题、适用范围、支持/不支持的事实或叙述类型，以及负责的任务/生产者。
2. 输入闭包：project/branch、候选身份/修订、原文 raw SHA、Delta/抽取提议 hash、parent、Contract、Pack、相关政策/检查器版本及可恢复输入 refs。
3. 证据需求：正文 source ID/raw hash、精确区间与原文引文、命题与操作的对应、覆盖要求、证据来源及核验方法。hash 验证字节，授权另查。
4. 实际执行记录：执行身份与授权来源、开始/完成状态、输入 hash、原始结果/诊断 refs；无结果或空 Findings 不能合成一次已执行检查。
5. 逐命题四态条件、意见冲突处理、适用性理由、无效化条件及允许人工裁决的明确范围。

下表是需在各 checker 落地时细化的最低判定表，不是已经实现的检查器：

| 命题/归属 | PASS 条件 | FAIL 条件 | UNKNOWN / ERROR |
|---|---|---|---|
| Q0 完整性与绑定，V022 | 实际执行且必需产物/执行记录闭包完整，scope/hash/version/来源适用 | 缺必需产物、错 hash/scope/旧版本，或必跑项未执行 | 结果不可确定为 UNKNOWN；解析/执行故障为 ERROR，均阻断 |
| 抽取对应与全文覆盖材料，V021；正式消费 V022～025 | 只对已核验的有限结构/对应命题给正向结果；语义资格另由适用检查决定 | 已证实正文/Delta 错绑、区间/引文错误或覆盖缺口 | 语义歧义、证据不足、未支持叙述为 UNKNOWN；抽取故障为 ERROR |
| Canon 前值/知识/生命周期，V023 | 所有适用有限条件及有效语义证据成立 | 过期前值、跨书、已证实无依据复活/越界知识 | 不确定事件或知识来源为 UNKNOWN；执行失败为 ERROR |
| 冻结世界机制，V024 | 适用 Pack 下命题有合格全文证据；合法引用/梦境等被正确区分 | 有效证据表明正文实际发生禁止机制 | 引述与实际事件不明、遗漏或相互冲突为 UNKNOWN；运行失败为 ERROR |
| Contract/接续，V025 | 所有适用必需/禁止/保护条件有证据；安静章节按自身合约判断 | 必需转移缺失、保护事实变化、实际知识/揭示边界被违反 | 合法回忆/视角复述有歧义时 UNKNOWN；不能只凭词面相似判 FAIL |

统一语义：PASS 表示实际执行且证据满足该有限命题；FAIL 表示已确定违反；UNKNOWN 表示已执行但证据不足/歧义/冲突/超出能力；ERROR 表示执行异常或无法产生合法结果。缺失、未执行、未实现和不适用是另外的适用性/执行状态，不伪造为 PASS。经政策证明不适用须保留理由，不能删除本来适用的必跑项。

## 4. 原文位置、叙述分类与覆盖

原始正文按 ADR-005 保留 UTF-8、BOM、CRLF、组合字符和末尾换行。主坐标采用零基、半开 Unicode code point 区间，引用必须等于原始解码字符串的该子串；若保存 byte offsets，必须由同一原始 UTF-8 推导并交叉核对，不能混用 code point、byte、grapheme。不做 trim/NFC/NFKC/换行替换后“近似命中”。

覆盖材料列出从 0 到原始正文末尾的完整分段，每段有 source/hash/区间和处理结果；空白或场景分隔符可以明确标类，不能直接漏掉。声明一段“已处理”也必须保留对应的分析结果或不支持原因。正文后半段缺失、覆盖分段区间重叠/越界、只有前场 Delta、与整章 hash 不同，均进入覆盖诊断。多个命题可以合法共用同一引文，不能把证据引用重叠误判为覆盖分段错误。

结构覆盖只证明所有字符有处理归属，不能证明每个语义命题都已正确识别。覆盖复查应查看原文与提议的差异，不能只回读抽取器列出的操作；同一模型重复自报完整、100% span 涂满或置信度 0.99 均不构成语义正确率。覆盖复查选择“从原文独立生成命题清单，再与抽取提议核对”，具体边界见第7节；未满足该方法适用范围时保持 UNKNOWN。

区分实际世界事件、角色亲见/获知、角色 Belief/传闻、引用、梦境、隐喻与作者未来意图。可以提交“角色听到某传闻”的合法认知提议，不把传闻内容自动提升为世界事实；当前有限语言无法表达的认知操作只留诊断，不静默新增操作或修改 KnowledgeState。合法叙述情境不是整段豁免：引用外实际发生的违规仍须检查。

## 5. 冲突与人工裁决

保留所有原始意见和证据。确定性硬失败持续阻断；语义意见互相冲突且无法判定时为 UNKNOWN/待裁决，不取平均分、最高置信度、多数票或“最后一个 PASS”。新的有效执行可显式替代技术失败记录，但不得删除失败历史或用空成功覆盖。

授权人工裁决须记录真实操作者、可信 grant/权限及版本、命题/适用范围、候选 raw hash、parent/Contract/Pack/政策、证据、理由和被裁决的冲突记录。人工只可处理政策允许的语义问题，不能覆盖错 hash、错 scope、缺执行、取消/撤权、过期许可、HEAD 竞争或确定的硬失败。实际身份由可信入口给出，不从文本中的 Owner/ALLOW、LLM角色标签或任意 self-signed JSON 推导。

尚未裁决、无权限裁决或裁决绑定旧候选均继续阻断。正文/Delta/parent/Contract/Pack/政策/授权版本变化使相关检查与裁决失效，原记录保留。创作满意度与提交权限分开。

## 6. Permit 与提交边界（V026 后续实现）

签发前核验完整必跑集合、实际执行来源、状态、所有候选/证据/政策绑定、当前 issuer/actor 权限、执行版本和有效期；只有全部适用项具备可接受证据才可签发。没有通用 SKIP/override。生产 grant 与 Permit 选择同一受控持久仓库的真实记录/不透明引用，见第7节。有效期采用显式版本政策必填参数，不设置默认数值；缺配置即阻断签发/消费，不要求在 V021 接口设计前先部署 P7。

CanonCommitService 在同一短事务边界重新核验当前 issuer/actor/grant、许可有效性/使用状态、request/execution fencing、取消/撤权、绑定和当前 HEAD，原子完成 CAS、许可消费、提交及持久收据。全文评估和模型调用在事务外。复用现有 ADR-006/章节提交机制；不引入第二 Canon 路径，也不只在 UI/Worker 校验一次。

成功提交按原稳定逻辑请求和载荷恢复原收据，attempt 不改变幂等身份；同键异载荷冲突。取消先赢则旧执行不能新提交，提交先赢则恢复原收据，不宣称回滚。P2 TEST Permit 继续被生产路径拒绝，不通过改标签获得生产权限。

## 7. 已收敛的设计及后续运行前置

### 7.1 零提议观察与有限语言

V021 采用独立抽取观察结果，可携带一个原有合法 NarrativeDelta 或不携带 Delta。数量从实际 operations 派生，不接受不一致的独立计数。无 Delta 仅表示“本次没有产生可编码注册操作”，不是“整章没有变化”、已完成检查或允许提交。

观察必须保留当前完整 assembly/prose raw hash、章节 source_id、parent/Contract/Pack/政策、生产者/方法版本、实际执行和原始结果、完整覆盖及未支持/未知诊断。非空提议仍用原有非空 NarrativeDelta，source_id须为本章候选来源。零提议不构造现有 ChapterCandidate，不填充虚假 NO_CHANGE，不改旧 Delta/P2/Canon 契约。合法 NO_CHANGE 仍需有具体事实、前值与证据，不能拿来填空。

未识别内容、无法编码的事件/实体/认知、歧义/冲突/遗漏复查不足均保留 UNKNOWN/UNSUPPORTED，不算“零提议成功”；未执行、超时、解析失败也不能转换为零提议。覆盖缺口、错绑定/区间/引文产生明确失败诊断。同一事实A→B→A或多次转移不得按净值或最后值合并为无变化，当前禁止重复target/path的语言无法编码时保留过程并阻断受影响语义。

这解决 V021 观察接口，不提前解决零 Delta 章节提交。未来若要接受该类章节，必须在 V026 集成前对章节载荷/同一提交服务作独立版本化兼容决定与测试；在此之前现有提交路径明确拒绝，不削弱非空语言。Q3允许安静章节按其合约被检查，不等于每种观察已具备提交载荷。

### 7.2 证据方法及全文复查

必跑检查由受控、版本化政策选取，以基础Q0–Q3命题及当前Contract/Pack适用要求形成完整集合；不能由caller删减或用测试profile代替生产政策。每个方法明确输入、支持范围、检查器/生产者版本和可接受依据：

| 方法 | 可接受的有限结论 | 不足/范围外处理 |
|---|---|---|
| 离线有限规则profile | 仅工程受控语句中实际执行的解析、注册事实提议、叙述分类/绑定/覆盖对照 | 不是自然网文全文能力或生产语义PASS；未知句型/语境/操作保留未支持区间与UNKNOWN |
| 模型/手工提议 | 候选操作、引文与可能命题供后续核验；原始输出和来源必须保留 | 不自授CheckExecution/语义PASS；置信度、重复自报完整、人工填写字段都不能单独放行 |
| 受信任的有限确定性检查 | 政策明确支持且实际执行的有限命题，可凭核对正确的输入/原文与规则证据判定 | 超出支持范围或缺依据为UNKNOWN，运行故障ERROR；不能套用到全部自然语义 |
| 获授权的语义裁决 | 仅政策列明可裁决的发生情境、认知/引用/梦境/歧义命题，有真实授权和完整证据 | 无授权或硬失败保持阻断；不是读者/市场证据，不替代未执行检查 |

全文覆盖采用两次不同职责：第一步生成抽取提议/分段处理记录；第二步独立从同一原文建立命题清单，先封存清单及其hash，再读取提议作对应核对，最后输出遗漏/冲突/未支持范围。两条发现路径只共享原始UTF-8、冻结的实体/事实身份与类型/别名目录及语法/方法政策，可共享原始坐标工具；不共享已分类AST或提议结果。目录不携带当前事实值或待实现转移，Contract/Pack完整hash仍作绑定，baseline只在发现之后的操作物化/preview使用，Contract要求由后续检查消费，不能把计划抄成已发生事实。

任一发现路径不得读取gold Delta、期望命题类型、预告遗漏位置、期望span或Contract.required的预期结果；gold仅用于外部断言。第二步不得只遍历提议列表，也不能靠共享抽取结果假装独立。否定/传闻/引用/时态等限定与完整命题一并保留，不能截掉限定词只比关键词。否定某次转移不推出旧值仍成立，不能据此补写NO_CHANGE。声明范围内独立识别的完整命题被提议遗漏或歪曲为实际事件时，对应核验为FAIL；无法确定的句式/语境才是UNKNOWN，不能把已证实遗漏改称无变化。若复查不能在声明范围内证明对应，结论UNKNOWN，不用“全字符已处理”替代语义依据。

离线有限profile先用于证明无答案泄漏的真实抽取/诊断执行，不能推广为生产自然全文判定。生产每项语义命题只能使用政策允许且有实际验证依据的方法/裁决；没有合格依据就不签Permit。方法/政策更新需版本化并使旧未提交证据失效，不设置模型置信度放行阈值。无需为V021接口提前建设P11校准平台，仍不得虚报尚无依据的模型正确率。

### 7.3 受控授权、许可记录与生命周期

授权来源选定受控管理记录与可信应用入口actor，沿用现有grant/control/fencing原则。新增生产角色的具体存储/接口由P7/V026实现，不能直接把InitializerGrant或P2 TEST来源换标签。grant至少绑定project/branch、允许动作、check ID/version或issuer职责、政策hash、enabled及授权版本。

检查者仅能产生其获准命题的执行记录；裁决者只处理政策授权的语义范围；issuer才有签发能力。逻辑职责可由同一Owner承担，不要求增加人数；单Owner共享写权限的既有威胁模型不升级为对抗性隔离。Worker/Prompt/caller JSON不能创建grant、自报可信actor或授予权限。

选择受控仓库持久保存不可变Permit正文与不透明引用；不先引入JWT/跨服务签名平台。引用本身不授权，签发/消费均读取真实记录和当前权限。Permit绑定稳定request、actor、候选/raw prose/Delta、parent、Contract/Pack/政策、完整必跑集合、真实检查/裁决记录、issuer、授权版本与execution fencing。只授权这次Canon提交，不授权Provider调用、发布或后续操作。

采用保守失效规则：相关checker/裁决者/issuer权限或相关政策变更提升适用作用域授权版本，使未提交旧证据与Permit不再适用。管理变更、取消、签发和提交按受控事务次序核验。成功提交仍用原request/载荷恢复持久收据，后来到期/撤权不抹去既成事实；恢复仍核身份和作用域，不重放旧写操作。

有效期采用版本化政策的显式正值max_lifetime与服务端issued_at/每张Permit显式expires_at，要求 issued_at < expires_at <= issued_at + max_lifetime，消费时当前服务时间必须早于expires_at。无默认TTL，不继承测试默认值；缺政策参数、未知/非法时间、过期或版本失效一律拒绝。数值、实际actor/grant名单及部署凭据是V026启用前必填配置与验证，不是当前设计未选择的架构分叉，也不在准备期编造。

### 7.4 冻结范围与剩余阻断

| 已选设计 | 后续仍需实现/取得的事实 | 不能据设计声称 |
|---|---|---|
| 独立观察允许零提议、原Delta/P2不变 | V021真实抽取/绑定/覆盖产物；零Delta提交若需要须另作版本化兼容决定 | Extractor已存在、零提议可提交 |
| 原文独立命题复查、有限方法接受及显式未知 | 实际backend、检查/裁决记录、支持范围正负例；自然全文能力仍未知 | 结构覆盖等于语义完整、模型置信度等于正确率 |
| 受控grant/actor、分责、版本失效、持久Permit、显式有效期 | P7/V026真实可信入口/配置、并发取消/撤权/恢复及保留测试 | 生产issuer或部署权限已就绪 |
| 原任务/阶段/门禁保留 | V021自己的实际开工条件或明确适用准入；当前V020仍IN_PROGRESS/G-P5未验证 | ADR接受等于IMPLEMENT/LIVE_CALL/CERTIFY放行 |

这些运行和实施前置继续阻断相应动作，不要求把未来实现当作接受本设计的循环前提。ADR只记录所选契约，不改变任务状态、最低验收或权限。

## 8. 备选方案与验证责任

纯模型 JSON/置信度方案缺乏来源、覆盖和权限依据，拒绝作为硬门禁。全人工逐章决策可处理歧义，但仍需绑定/授权与硬检查，且不能冒称自动抽取。选定的混合方案把可确定的结构错误立即拒绝，保留未决语义，便于分阶段检验；它不会自动得到全文正确率。

V021 验证同章 hash、叙述类型、全文遗漏诊断、错误/缺失/冲突证据；V022 验证真实 CheckExecution 与必跑闭包；V023～025 验证各命题和合法对照；V026 验证伪 issuer/旧证据/人工同意无效及双次权限核验。详细正反例见准备矩阵。手工映射和本地结构测试不能冒充自动 Extractor、真实 Provider、真人/市场或正式 CI 证据。

正式接受以非模板 ADR_DECISION 绑定已审阅方案及依据，并由机器登记引用；接口实现仍须满足独立任务准入。运行能力只有在相应代码、实际测试及后续工程验收完成后成立。本轮不改变任何已接受 ADR。
