## 🎯 项目目标

### 原始问题
1. **状态判断分散** - 多个决策源，容易不一致
2. **缺乏契约概念** - 无法自动验证章节质量
3. **连续性无保证** - 时间、人物、状态可能不连贯
4. **人工检查为主** - 效率低，容易遗漏

### 解决方案
1. **Story Bible 驱动** - 单一真相源，自动生成契约
2. **统一状态管理** - ProductionState 作为唯一决策源
3. **自动化验证** - 契约、连续性、状态三重验证
4. **渐进式集成** - 不破坏现有功能，平滑过渡

## 🎯 核心功能

### 1. Story Bible 驱动开发

**创新**: 单一真相源 → 自动生成契约 → 自动验证

**流程**:
```yaml
Story Bible (1,300行)
    ↓
自动生成 30个契约
    ↓
自动验证章节
    ↓
减少人工检查 80%
```

**优势**:
- ✅ 保证一致性
- ✅ 自动化验证
- ✅ 易于维护
- ✅ 可追溯性

### 2. 契约验证系统

**验证项**:
- **硬约束** (必须满足): 主角名字、日期
- **软约束** (建议满足): 地点、人物、线索

**验证结果**:
```python
ValidationResult(
    passed=True/False,
    errors=[...],    # 硬约束违反
    warnings=[...]   # 软约束违反
)
```

**集成点**:
- Serial 生成后自动验证
- Mint 发布前再次验证
- 人工审核可查看报告

### 3. 统一状态管理

**6种状态**:
```
GENERATED → HUMAN_APPROVED → PUBLISHED
     ↓              ↑
  BLOCKED      (审核循环)
     ↓
INVALIDATED
     ↓
NEEDS_REVISION
```

**决策方法**:
- `can_export()` - 是否可以发布
- `can_proceed_next()` - 是否可以继续下一章
- `can_revise()` - 是否可以修改
- `can_publish()` - 是否可以发布

**优势**:
- ✅ 单一决策源
- ✅ 清晰的转换规则
- ✅ 自动阻塞机制
- ✅ 审计追踪

### 4. 连续性保证

**5项检查**:
1. **主角一致** - 主角名字不能改变
2. **时间前进** - 时间只能往前走
3. **章节连续** - 章节号必须连续
4. **人物存在** - 已出现人物不能消失
5. **死者不复活** - 死亡人物不能复活

**检测方式**:
```python
errors = state2.validate_continuity(state1)
# ['时间倒流: 2013-01-20 → 2013-01-15']
```

### 5. 渐进式集成

**双轨制策略**:
- **新功能**: 使用 ProductionState
- **现有功能**: 保留旧字段（标记为 advisory）
- **未来**: 逐步迁移

**优势**:
- ✅ 不破坏现有功能
- ✅ 平滑过渡
- ✅ 风险可控
- ✅ 易于回滚
