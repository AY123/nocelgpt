### Task 2.2: 定义 StoryState（3天）

**位置**: `AI-Novel-Runtime/runtime/contract/story_state.py`

**核心结构**:

@dataclass
class StoryState:
    """故事状态：跨章节共享的世界状态"""
    
    # 时间和地点
    current_date: str
    current_location: str
    
    # 主角状态
    protagonist: Character
    
    # 人物关系图
    characters: Dict[str, Character]
    relationships: Dict[Tuple[str, str], Relationship]
    
    # 未完成的线索
    open_threads: List[Thread]
    resolved_threads: List[Thread]
    
    # 世界事实
    world_facts: Dict[str, Any]
    
    def validate_continuity(self, prev_state: 'StoryState') -> List[str]:
        """验证与上一个状态的连续性"""
        errors = []
        
        # 主角名字不能变
        if self.protagonist.name != prev_state.protagonist.name:
            errors.append(f"主角名字改变: {prev_state.protagonist.name} → {self.protagonist.name}")
        
        # 时间只能前进
        if self.current_date < prev_state.current_date:
            errors.append(f"时间倒流: {prev_state.current_date} → {self.current_date}")
        
        # 人物不能凭空消失
        for char_id in prev_state.characters:
            if char_id not in self.characters:
                errors.append(f"人物消失: {char_id}")
        
        return errors
    
    def extract_from_draft(draft: ChapterDraft) -> 'StoryState':
        """从章节草稿中提取状态"""
        pass
```

### Task 2.3: 统一 ProductionState（2天）

class ProductionState(Enum):
    """统一的生产状态"""
    
    GENERATED = "generated"  # 已生成，未验证
    NEEDS_REVISION = "needs_revision"  # 需要修改
    BLOCKED = "blocked"  # 被阻塞（依赖未满足）
    HUMAN_APPROVED = "human_approved"  # 人工审核通过
    PUBLISHED = "published"  # 已发布
    INVALIDATED = "invalidated"  # 已作废
    
    def can_export(self) -> bool:
        """是否可以导出"""
        return self in [
            ProductionState.HUMAN_APPROVED,
            ProductionState.PUBLISHED
        ]
    
    def can_proceed_next(self) -> bool:
        """是否可以继续下一章"""
        return self in [
            ProductionState.HUMAN_APPROVED,
            ProductionState.PUBLISHED
        ]
    
    def can_revise(self) -> bool:
        """是否可以修改"""
        return self in [
            ProductionState.GENERATED,
            ProductionState.NEEDS_REVISION
        ]
```

### Task 2.4: 重构 Serial 使用新契约（5天）

**位置**: `AI-Novel-Runtime/runtime/serialize/loop.py`

**核心逻辑**:
```python
def run_serial(project_dir: Path, ...):
    """串行生成30章"""
    
    # 1. 加载 Story Bible
    bible = load_story_bible(project_dir)
    
    # 2. 初始化状态
    current_state = create_initial_state(bible)
    
    # 3. 逐章生成
    for chapter_num in range(1, 31):
        # 3.1 检查上一章状态
        if chapter_num > 1:
            prev_chapter = load_chapter_final(chapter_num - 1)
            if not prev_chapter.production_state.can_proceed_next():
                print(f"❌ 第{chapter_num-1}章状态为 {prev_chapter.production_state}，无法继续")
                break
        
        # 3.2 生成契约
        contract = generate_contract(bible, chapter_num, current_state)
        
        # 3.3 生成章节
        draft = generate_chapter(contract, current_state)
        
        # 3.4 验证契约
        validation = contract.validate(draft)
        if not validation.passed:
            draft.production_state = ProductionState.BLOCKED
            print(f"❌ 第{chapter_num}章验证失败: {validation.errors}")
            save_chapter_final(draft)
            break
        
        # 3.5 提取新状态
        new_state = StoryState.extract_from_draft(draft)
        
        # 3.6 验证连续性
        continuity_errors = new_state.validate_continuity(current_state)
        if continuity_errors:
            draft.production_state = ProductionState.BLOCKED
            print(f"❌ 第{chapter_num}章连续性错误: {continuity_errors}")
            save_chapter_final(draft)
            break
        
        # 3.7 更新状态
        current_state = new_state
        draft.production_state = ProductionState.GENERATED
        
        # 3.8 保存
        save_chapter_final(draft)
        print(f"✓ 第{chapter_num}章生成完成")
```

**实现步骤**:
1. 修改 `run_serial()` 添加状态检查
2. 实现 `generate_contract()` 从 Story Bible 生成契约
3. 在生成后立即验证契约和连续性
4. 失败时设置 BLOCKED 状态并停止
5. 添加集成测试

**验收标准**:
- ✅ 无法跳过 BLOCKED 章节
- ✅ 契约违反会被检测
- ✅ 连续性错误会被检测
- ✅ 状态正确传递

## 🚨 风险和应对

### 风险1: 状态提取不准确
**应对**: 
- 从简单的字段开始（date, location）
- 复杂字段（人物关系）可以手动标注
- 迭代改进提取算法

### 风险2: 契约过严，无章节能通过
**应对**:
- 渐进式调整阈值
- 允许人工覆盖（override）
- 记录每次失败原因

### 风险3: 与现有代码冲突
**应对**:
- 保留旧字段作为 advisory
- 渐进式迁移，不做大爆炸
- 充分测试兼容性
