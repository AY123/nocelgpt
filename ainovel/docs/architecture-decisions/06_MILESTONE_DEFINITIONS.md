# ANovel V2 项目实施里程碑定义

**版本**: v1.0  
**制定日期**: 2026-09-18  
**实施周期**: 3-6 个月  
**关键决策点**: M3（3 个月后）  

---

## 一、里程碑体系概览

### 1.1 里程碑层次

```
M0: 准备阶段（当前）
  ↓
M1: Genre 系统重构完成（Month 1）
  ↓
M2: 生产流程优化完成（Month 2）
  ↓
M3: 30 章基线建立（Month 3）← 关键 Go/No-Go 决策点
  ↓
M4-M6: 商业验证（Month 4-6，仅在 M3 通过后执行）
```

### 1.2 验收标准分级

| 级别 | 说明 | 失败后果 |
|------|------|----------|
| 🔴 **Must Pass** | 必须通过，否则阻断 | 延长当前阶段，修复后再验收 |
| 🟡 **Should Pass** | 应该通过，但可接受有限偏差 | 记录风险，但可进入下一阶段 |
| 🟢 **Nice to Have** | 加分项，不强制 | 不影响里程碑通过 |

### 🚨 Go/No-Go 决策规则

#### ✅ Go（继续投入）

如果满足以下**全部条件**：
1. 都市/玄幻各 30 章完整生产 ✅
2. 前 3 章盲评 **> 7/10** ✅
3. 前 10 章留存度 **> 6/10** ✅
4. 30 章完整性复盘 **0 重大缺陷** ✅

**决策**：
→ 进入 Phase 4-6（Month 4-6）
→ 建立金样集
→ 校准评分系统
→ 验证自动修订
→ 100 章规划

#### ❌ No-Go（暂停扩张）

如果**任何一项**未通过：
1. 前 3 章盲评 < 7/10 ❌
2. 前 10 章留存度 < 6/10 ❌
3. 30 章有重大缺陷 ❌

**决策**：
→ **不继续投入 Phase 4-6**
→ 回到问题定位
→ 分析失败原因：
  - 题材系统？（仍有类型污染）
  - 质量系统？（AI 味太重、钩子不够）
  - 流程问题？（生产不稳定）
→ 针对性修复
→ 重新验证
→ **不谈 100 章、不扩展新题材、不增加新功能**

### 失败处理

**如果 M3 不通过**：

1. **召开失败分析会议**
   - 识别根本原因
   - 不是"再努力一点"，而是"哪里设计错了"

2. **可能的根本原因**：
   - Genre 系统仍有漏洞（题材污染未彻底解决）
   - 质量系统不够（AI 味、钩子、声音仍有问题）
   - Prompt 模板不够强（约束表达不清）
   - 人工验证标准太高（需要调整期望）

3. **修复策略**：
   - 不能只是"微调参数"
   - 需要结构性改进
   - 可能需要回到 M1/M2 重新设计

4. **时间投入**：
   - 最多再投入 1 个月修复
   - 如果仍不通过，考虑更根本的方向调整

### 完成标志

✅ 都市/玄幻各有 30 章人工验证通过的基线，前 3 章真的抓人，30 章真的完整。

### 时间预估

**4 周**

## 九、关键成功因素

### 不能妥协的原则

1. **M3 是硬门槛**
   - 前 3 章 < 7 分 = 不通过
   - 30 章有重大缺陷 = 不通过
   - 不能因为"已经投入 3 个月"就降低标准

2. **验收标准不能临时调整**
   - 里程碑开始前就明确标准
   - 不能因为接近完成就放宽要求

3. **失败不是耻辱，继续错误方向才是**
   - M3 不通过 = 及时止损
   - 继续投入到错误方向 = 更大浪费

### 风险提示

1. **范围蔓延风险**
   - 症状：M2 还没完成，就开始讨论 M4
   - 缓解：严格按里程碑顺序推进

2. **标准放松风险**
   - 症状：盲评 6.5 分，"差不多就行了"
   - 缓解：坚持 > 7 分的标准

3. **完美主义陷阱**
   - 症状：M1 已通过，但想"再优化一下"
   - 缓解：通过就立即进入下一阶段
