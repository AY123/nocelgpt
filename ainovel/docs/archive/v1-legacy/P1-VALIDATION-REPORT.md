## P1-2: text_integrity误报 ❌ 严重问题

**结论**: text_integrity检测器存在**100%误报率**

### 证据数据

**前30章统计**:
```
状态分布:
  review_required: 30/30 章 (100.0%)

触发原因:
  word_internal_punctuation: 30/30 次 (100%)
```

### 误报根因

**检测器问题**: `word_internal_punctuation` 检查逻辑有缺陷

**触发模式**: 中文分词算法将正常的中文标点判断为"字内标点"

**典型误报案例**:

1. **章节1**: 
   - 触发: `'晶矿。城'`
   - 实际: `镐柄上,却没有立即动作。三个月前,就是这条矿道`
   - 分析: 句号后紧跟中文，分词器误判为"字内标点"

2. **章节2**:
   - 触发: 42个实例
   - 实际: `片,贴近嘴唇却没再往前。妹妹躺在身后的临时铺位`
   - 分析: 逗号、句号在正常位置，但分词器误判

3. **章节3**:
   - 触发: 56个实例
   - 实际: `倒塌的岩石堆后站了起来。对方的左臂垂落着,肩膀`
   - 分析: 标点符号使用完全正常

### 问题严重程度

- **误报率**: 100% (30/30章)
- **影响范围**: 所有章节
- **实际后果**: 
  - ❌ 所有章节都被标记为`review_required`
  - ❌ 审核报告误认为"质量问题"
  - ❌ 影响生产决策判断

### 根本原因

**检测器设计缺陷**:
```python
# 当前逻辑（推测）:
# 检测器使用字符级分词
# 将"。段" / "，那" / "？他"视为"标点嵌入字内"
# 但这在中文中是完全正常的句间/词间标点
```

**中文特性被忽略**:
- 中文不使用空格分词
- 标点后直接跟随下一个字是正常的
- 英文的"word-internal punctuation"概念不适用于中文

### 修复方案

#### 方案A: 禁用word_internal_punctuation检查（快速）

**时间**: 10分钟  
**风险**: 零（只是关闭一个误报检测器）

```python
# runtime/execution/text_integrity.py
def check_word_internal_punctuation(text):
    # FIXME: 中文分词误报率100%，临时禁用
    return []  # 或者添加语言检测，仅对英文启用
```

**优点**:
- 立即解决100%误报问题
- 零风险
- 不影响其他检查

**缺点**:
- 不检测真正的字内标点错误（如果存在）
- 需要后续改进

#### 方案B: 改进中文分词逻辑（正确）

**时间**: 2-3天  
**风险**: 中等（需要测试新分词器）

**实现**:
1. 添加语言检测
2. 中文文本使用jieba/pkuseg分词
3. 检查词内是否包含标点（而非字内）
4. 添加中文标点白名单

**优点**:
- 正确处理中文
- 保留对英文的检查能力
- 长期可维护

**缺点**:
- 需要引入分词库
- 需要测试和调优
- 时间较长

#### 方案C: 调整检测阈值（折中）

**时间**: 1小时  
**风险**: 低

**实现**:
```python
# 只在实例数过多时才触发（如>100次）
if len(instances) > 100:
    return finding
else:
    return None  # 容忍少量误报
```

**优点**:
- 快速实施
- 减少误报
- 保留部分检测能力

**缺点**:
- 仍然有误报（只是更少）
- 阈值选择主观

### 推荐方案

**短期（本周）**: 方案A（禁用）
- 立即解决100%误报
- 不阻塞生产

**中期（下周）**: 方案B（改进）
- 正确实现中文分词
