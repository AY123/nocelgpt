# ANOVEL 百万字长篇生产系统架构

> 版本：v1.0  
> 目标：构建面向中文网文爆款生产的多模型作品操作系统  
> 适用范围：起点中文网式男频商业长篇，目标百万字以上持续生产  
> 原则：质量优先、商业导向、留存驱动、长期可维护、全链路可审计

---

## 1. 项目定位

ANOVEL 不是一个单纯的“AI 写作工具”，而是一个面向中文网文爆款生产的**长篇作品操作系统**。

它的核心目标不是“生成一章文本”，而是持续完成以下任务：

- 选题定位
- 开书策划
- 长弧规划
- 章节生成
- 正文修订
- 质量评审
- 事实回流
- 版本冻结
- 作品审计
- 上架验证
- 百万字稳定生产

ANOVEL 的最终目标是让系统能够稳定产出：

1. 小说质量高  
2. 商业价值高  
3. 读者留存强  
4. 长期维护好

ANOVEL 采用分层式架构，核心分为 8 层。

```text
┌────────────────────────────────────────────────────────────┐

├────────────────────────────────────────────────────────────┤
│  0. 商业输入层                                             │
│  - 平台题材趋势 / 竞品分析 / 读者画像 / 付费模型            │
├────────────────────────────────────────────────────────────┤
│  1. 选题与定位层                                           │
│  - 题材定位 / 核心卖点 / 受众定位 / 风险评估                │

│  4. 章节生产层                                             │
│  - Chapter Objective / Draft / Revision / Final Selection │
├────────────────────────────────────────────────────────────┤
│  5. 质量评审层                                             │

│  6. 事实回流层                                             │
│  - Fact Extraction / Normalize / Approve / Mint / Consume │

│  - Run Manifest / Checkpoint / Replay / Baseline Compare   │
```

## 4. 核心设计原则

### 4.1 生成与评审分离
正文生成与质量评审必须拆开，避免模型自我确认。

### 4.2 规划与落笔分离
长弧、卷结构、章节目标必须先规划，再落笔。

### 4.3 事实与正文分离
正文是叙事输出，事实是系统状态，二者不能混写。

### 4.4 商业与文学分离
商业定位、卖点、付费点与正文可读性、人物可信度、节奏控制必须分别管理。

### 4.5 局部优化不能代替全局稳定
单章变好不等于长篇能稳。

## 5. 多模型协作定位

ANOVEL 采用 Claude、GPT-5.5、Kimi-k3 三模型协同生产。

### 5.1 Claude Opus 5
**定位**  
总策划、长弧导演、结构总控、复杂一致性推理

**适合做**
- 题材定位分析
- 长弧规划
- 章节目标设计
- 结构一致性检查
- 设定冲突分析
- 人物动机建模

**不适合做**
- 高频正文润色
- 快速批量草稿
- 逐句语言修饰

---

### 5.2 GPT-5.5
**定位**  
正文润色、商业表达、留存优化、中文语言打磨

**适合做**
- 章末钩子增强
- 正文润色
- 对话自然化
- 节奏优化
- 可读性增强
- 商业阅读感优化

**不适合做**
- 超长跨度全局规划
- 世界观总控
- 高复杂事实统筹

---

### 5.3 Kimi-k3
**定位**  
快速草稿、中文长文铺陈、场景推进初稿

**适合做**
- 章节初稿
- 批量草稿
- 场景扩写
- 多版本候选生成

**不适合做**
- 最终终审
- 长篇一致性裁决
- 高难度结构拍板

## 6. 生产闭环

ANOVEL 的生产闭环分为 4 个循环。

### 6.1 商业闭环
题材定位 → 卖点设计 → 开篇吸引 → 付费点设计 → 留存优化 → 商业验证

### 6.2 叙事闭环
长弧规划 → 章节目标 → 正文生成 → 节奏控制 → 高潮推进

### 6.3 事实闭环
正文生成 → 新事实提取 → 审批 → mint → 下一章消费 → 状态更新

### 6.4 质量闭环
生成 → 评审 → 修订 → 再评审 → 基线冻结 → 版本比较

## 8. 关键生产层说明

### 8.1 选题与定位层
负责回答：
- 写什么
- 给谁看
- 为什么能卖
- 为什么能连载

输出：
- 题材定位
- 核心卖点
- 目标读者
- 风险评估

---

### 8.2 长弧规划层
负责回答：
- 前 30 章怎么写
- 前 100 章怎么走
- 什么时候升级、反转、换地图
- 怎么保证百万字不散

输出：
- 30 章基线
- 100 章长弧
- 卷结构
- 高潮点
- 付费点
- 地图切换点

---

### 8.3 世界与角色状态层
负责维护：
- 世界规则
- 能力体系
- 角色状态
- 关系变化
- 伏笔状态

目标：
- 防止设定漂移
- 防止人设漂移
- 防止长篇断裂

---

### 8.4 章节生产层
每章必须明确：
- 本章目标
- 本章冲突
- 本章信息增量
- 本章钩子
- 本章必须消费的旧事实

---

### 8.5 质量评审层
评审维度包括：
- 结构
- 人物
- 设定
- 可读性
- 节奏
- 商业性
- 留存性
- 长篇风险

---

### 8.6 事实回流层
负责：
- 提取事实
- 规范化
- 审批
- mint
- 回流到下一章

这是百万字不崩的关键。

---

### 8.7 运行与审计层
负责：
- run manifest
- checkpoint
- resume
- replay
- baseline compare
- archive

目标是让每次生产都可追溯、可复盘、可比较。

- 题材定位
- 30 章基线
- 角色卡
- 世界卡

### 第二阶段

- Kimi-k3 出初稿
- GPT-5.5 做润色

### 第三阶段
- 评审体系接入
- 修订体系接入
- 事实回流接入

### 第四阶段
- 10 章、30 章、100 章版本冻结
- 基线比较
- 真实作品验证

---

## 12. 团队执行原则

### 12.1 先做事实入口
先统一文档和事实源，再谈大规模生产。

### 12.2 先做真实基线
先跑出 30 章真实基线，再扩到 100 章。

### 12.3 先做质量锚点
先有人工金样集和校准，再放大自动化。

### 12.4 先做闭环
先让事实回流、评审、修订、归档形成闭环，再追求效率。

---

## 13. 最终目标

ANOVEL 的最终目标不是“会写小说”，而是：

> 构建一个可审计、可回放、可校准、可长期维护的中文网文百万字生产系统，让优秀小说的结构、节奏、卖点、留存与长线稳定能力，变成可复制的工程能力。
