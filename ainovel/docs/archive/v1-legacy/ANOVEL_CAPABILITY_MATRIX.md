# ANovel 能力矩阵

> 用途：区分“工程完成”与“产品完成”，避免把 schema、consumer、测试数量误认为正文质量或商业验证。
>
> 证据优先级：当前代码与运行结果 > 测试 > Standard / ADR > README / ROADMAP > 审核报告 > 推测。

## 1. 使用方式

- `schema`：是否存在可版本化的结构定义。
- `consumer`：是否存在真实消费该能力的运行路径。
- `tests`：是否有自动化验证。
- `live proof`：是否有真实运行结果或 replay 证明。
- `product proof`：是否有面向小说正文结果的人工或实测证据。
- `commercial proof`：是否有真实平台或真实商业反馈。

> 说明：字段为空不代表能力不存在，只代表当前仓库里还没有被系统化记录。

## 3. 当前结论

- 工程能力已经较完整，但产品能力仍在补证据。
- 当前最重要的空白，不是更多模块，而是正文质量与商业真值。
- 后续推进应优先补齐：中文语域、长度、角色声音、Winner 一致性、30 章真实基线。

## 4. 后续维护规则

当出现以下情况时，应更新本文件：

1. 新增真实消费者。
2. 新增测试或真实运行结果。
3. 某项能力从“待补”变成“部分”或“是”。
4. 形成新的产品级或商业级证据。
