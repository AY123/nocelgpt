# ANOVEL 学习闭环规范

> 版本：v1.0  
> 适用范围：ANOVEL 百万字长篇生产系统  
> 目标：定义语料证据、长弧运行、真实作品、评审结果和平台反馈如何反向更新系统策略  
> 原则：学习来源分层、反馈闭环明确、策略版本化、更新可审计

---

## 1. 文档目的

ANOVEL 不能只是一套“会生成小说”的系统，它必须具备持续学习能力。

也就是说，系统不能永远用同一套规则写所有书，而要能根据：

- 语料分析结果
- 章节生产结果
- 人工评审结果
- 自动修订结果
- 长篇运行结果
- 真实平台反馈

不断修正自己的定位、长弧、评分、开书和事实回流策略。

本规范定义 ANOVEL 的学习闭环。

---

## 2. 学习闭环总原则

### 2.1 反馈必须分层
不同来源的反馈不能混成一团：

- 语料证据是外部知识
- 正文结果是项目产物
- 评审结果是质量信号
- 平台数据是真实商业信号

### 2.2 反馈必须版本化
任何反馈一旦影响系统策略，都必须对应一个明确版本。

### 2.3 反馈必须可追踪
必须知道：
- 这条反馈来自哪里
- 谁生成的
- 影响了什么策略
- 后续结果如何

### 2.4 反馈不能静默改系统
系统策略更新必须显式记录，不能悄悄变更。

### 2.5 反馈必须可回滚
如果某次学习方向错误，必须能回退到上一个稳定版本。

---

# 3. 学习闭环的 4 个平面

ANOVEL 的学习闭环分为四个平面：

1. 语料知识平面
2. 生产结果平面
3. 评审判断平面
4. 真实平台反馈平面

---

## 3.1 语料知识平面
来自优秀小说、失败小说、题材样本、叙事模式、结构范式的抽象证据。

### 作用
- 指导选题
- 指导长弧
- 指导卖点
- 指导开篇结构
- 指导风险规避

### 形式
- `CorpusSnapshot`
- `BookNarrativeProfile`
- `GenesisEvidencePack`

### 规则
- 只能作为抽象证据
- 不能直接写入事实账本
- 不能直接泄露连续原文
- 不能作为正文模板硬复制

---

## 3.2 生产结果平面
来自 ANOVEL 自己生产的正文、评审、修订和事实流转结果。

### 作用
- 校准系统实际表现
- 检查正文是否符合目标
- 判断自动修订是否有用
- 判断长弧是否成立

### 形式
- 章节正文
- ReviewReport
- RevisionDiff
- FactRecord
- Run Snapshot

### 规则
- 必须可回放
- 必须可比较
- 必须有 provenance
- 必须有版本号

---

## 3.3 评审判断平面
来自 Claude、GPT-5.5、人工评审、仲裁和金样集校准的判断结果。

### 作用
- 区分好坏
- 指导修订
- 决定是否发布
- 识别风险维度

### 形式
- `ReviewReport`
- 金样集评分
- 评审仲裁记录
- 维度校准结果

### 规则
- 未校准维度不能直接强决策
- 评分系统必须独立于生成系统
- 必须保留评分版本

---

## 3.4 真实平台反馈平面
来自真实读者行为、上架后表现、留存数据和付费数据。

### 作用
- 校准商业判断
- 校准留存模型
- 校准开书策略
- 校准评分权重

### 形式
- 点击率
- 三章留存
- 十章追读
- 首订
- 追订
- 弃书位置
- 付费转化
- 月票 / 打赏数据

### 规则
- 这是最高优先级反馈
- 一旦出现真实平台数据，应优先校准商业模型
- 不得用模拟数据冒充真实结果

---

# 4. 学习闭环结构

ANOVEL 的学习闭环可以表示为：

```text
语料证据
→ 选题 / 长弧 / 开书策略
→ 正文生产
→ 评审 / 修订 / 事实流转
→ 长弧运行结果
→ 平台反馈
→ 策略更新
→ 新版本系统
```

---

# 5. 学习闭环中的核心对象

---

## 5.1 `CorpusEvidence`
语料层输出的抽象证据。

### 字段建议
```json
{
  "evidence_id": "CE-001",
  "source_type": "high_performance_work",

  "risk_notes": ["中段可能疲劳"],
  "version": "v1.0"

```

---

## 5.2 `ProductionOutcome`
系统生产结果。

### 字段建议
```json
{
  "story_id": "STORY-001",
  "chapter_id": "CH-001",
  "quality_score": 85,
  "commercial_score": 82,
  "retention_score": 90,
  "long_term_score": 78,
  "revision_count": 2,
  "facts_minted": 5
}
```

---

## 5.3 `ReviewSignal`
评审信号。

### 字段建议
```json
{
  "review_version": "v1.0",
  "dimension": "retention",
  "score": 4,
  "confidence": 0.88,
  "calibration_state": "calibrated",
  "source": "gpt-5.5"
}
```

---

## 5.4 `PlatformSignal`
真实平台信号。

### 字段建议
```json
{
  "release_id": "REL-001",
  "click_rate": 0.12,
  "three_chapter_retention": 0.68,
  "ten_chapter_retention": 0.41,
  "subscription_rate": 0.09,
  "drop_off_point": "CH-004"
}
```

---

## 5.5 `StrategyUpdate`
策略更新记录。

### 字段建议
```json
{
  "strategy_id": "STR-001",
  "trigger": "platform_signal",
  "changed_modules": [
    "opening_template",
    "retention_weight",
    "commercial_scoring"
  ],
  "reason": "开篇留存低于预期",
  "version_from": "v1.0",
  "version_to": "v1.1"
}
```

# 6. 学习来源分层

ANOVEL 的学习来源分 3 级：

## 6.1 一级：确定性学习来源
这类反馈最可靠，可以直接影响系统规则。

包括：
- 设定冲突
- 事实冲突
- 明确的审计错误
- 真实平台数据
- 版本回放差异

---

## 6.2 二级：诊断性学习来源
这类反馈有价值，但不能单独作为强决策依据。

包括：
- 模型评分
- 人工评审
- 金样集结果
- 盲评结果
- 多模型比较结果

---

## 6.3 三级：预测性学习来源
这类反馈用于趋势观察，不直接作为最终真值。

包括：
- 模拟留存
- 模拟付费
- 模拟追读
- AI judge 倾向分

---

# 7. 策略更新机制

---

## 7.1 触发策略更新的情况

### 结构类
- 多次出现同类结构问题
- 某类章节重复疲劳
- 某类开篇留存差

### 商业类
- 卖点弱化
- 付费点不清
- 平台适配不佳

### 留存类
- 开篇点击低
- 章末钩子弱
- 追读衰减快

### 长篇类
- 人设漂移
- 设定冲突
- 伏笔回收率低
- 中后期节奏下滑

---

## 7.2 策略更新方式

策略更新不能直接改代码或 prompt，而应该先形成策略记录，再进入版本更新。

步骤如下：

1. 收集反馈
2. 验证反馈类型
3. 判断是否可作为强信号
4. 提出策略更新建议
5. 生成新版本策略
6. 重新跑基线
7. 记录变化

---

## 7.3 更新对象

可被更新的对象包括：

- 选题模板
- 开篇模板
- 评分权重
- 长弧规划逻辑
- 角色卡模板
- 事实回流规则
- 发布门槛
- 商业判断阈值

---

# 8. 学习闭环的版本控制

## 8.1 为什么要版本控制
因为 ANOVEL 不是“想改就改”的系统。  
每次策略变化都会影响正文质量和商业结果。

## 8.2 版本控制对象
- `opening_template_version`
- `scoring_version`
- `arc_version`
- `review_version`
- `fact_flow_version`
- `release_version`

## 8.3 版本切换原则
- 不在生产中静默切换
- 必须有回放
- 必须有对照
- 必须能回滚

---

# 9. 学习闭环与模块关系

### 9.1 对选题模块的影响
语料证据和平台反馈会更新题材选择和卖点策略。

### 9.2 对长弧模块的影响
长跑结果和留存趋势会更新卷结构、节奏和地图切换点。

### 9.3 对评分模块的影响
金样集、人工评审和真实平台数据会更新评分权重与门槛。

### 9.4 对开书模板的影响
成功开篇样本会进入模板，失败样本会形成负样本规则。

### 9.5 对事实流转的影响
长期运行中暴露的冲突模式会更新事实审批和回流规则。

---

# 10. 常见学习错误

## 10.1 把预测信号当真值
问题：把模型猜测当成真实平台反馈。  
后果：错误优化。

## 10.2 不区分反馈层级
问题：把语料证据、评审信号、平台数据混在一起。  
后果：策略混乱。

## 10.3 静默改策略
问题：没版本记录就直接改。  
后果：无法回放和回滚。

## 10.4 只学习成功案例
问题：只看高分样本，不看失败样本。  
后果：系统对风险无感。

## 10.5 学习太快
问题：数据不足就频繁改方向。  
后果：系统不稳定。

---

# 11. 最小可执行版本

如果团队先做 MVP，建议先落地以下内容：

1. `CorpusEvidence` 记录
2. `ProductionOutcome` 记录
3. `ReviewSignal` 分层
4. `StrategyUpdate` 版本化
5. 真实平台信号接入
6. 回放与回滚机制

---

# 12. 结论

ANOVEL 的学习闭环不是为了“更聪明地调参”，而是为了让系统在长期生产中文网文时，能够持续吸收：

- 好作品的规律
- 坏作品的警告
- 自己运行中的偏差
- 真实平台的读者反馈

并把这些反馈变成可版本化、可审计、可回放的下一代生产策略。
