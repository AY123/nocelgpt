# AINovel 题材系统最终复审核报告

**审核日期**：2026-09-07  
**审核对象**：最新工作总结、代码、测试及 `novel-dushi` 产物  
**审核结论**：**不通过“优秀/长篇生产就绪”验收**  
**当前评级**：**C+ 至 B-，受控小样本可用，长篇生产不建议启动**

## 一、结论先行

本轮改造有实质进展：都市 fallback 已生成 `progression_system(type=wealth)`，outline 合成已开始优先使用新 Progression，chapter finalizer 代码中也加入了严格题材校验分支。

但“38 个测试全部通过、无 warnings、3 章产物已完成全链路验证、可稳定受控生产 3–10 章”等结论，目前仍不能由仓库证据支持。复核得到以下事实：

- 定向测试实际为 **44 passed, 38 warnings**；
- 一组 outline schema 回归测试实际 **1 failed, 54 passed, 6 warnings**；
- 玄幻回归中“要求 `power_system`”的测试返回 `False`，但由于使用 `return` 而非 `assert`，pytest 仍将其计为 passed；
- 已生成的 3 个 `ChapterFinal` 的 `genre_profile_id` 和 `genre_contract_version` 均为 `null`；
- 章节 finalizer 读取 outline 使用了不存在的 `runtime.outline.loader`，异常被吞掉，导致真实章节验证可能降级为“未知题材”；
- outline fallback 的都市 world 默认内容仍包含“周期性灾变、旧纪元真相、力量成长”等奇幻/末世骨架，而当前契约只扫描少数字段，仍会判定通过；
- `novel-dushi` 只有 3 章，没有 5 章或长篇真实产物。

因此准确状态应为：

> **题材系统已完成一部分架构修复，可在人工逐章审核下进行小样本都市试跑；但尚未达到优秀，也不具备直接启动 30+ 章长篇都市生产的证据。**

## 二、测试复核

### 2.1 定向题材测试

执行：

```bash
cd AI-Novel-Runtime
python3 -m pytest -q \
  tests/test_genre_detection.py tests/test_p0_fixes.py \
  tests/test_xuanhuan_regression.py tests/test_end_to_end_genre.py \
  tests/test_genre_contract.py tests/test_progression.py \
  tests/test_downstream_progression.py tests/test_p0_integration.py
```

结果：**44 passed, 38 warnings**。

这些 warning 不是无害噪音：大量测试仍以 `return True/False` 报告结果。尤其 `test_power_system_in_xuanhuan()` 实际返回 `False`，原因是 fallback 已切到 `progression_system`、不再提供 `power_system`；pytest 因没有 assert 仍将该测试计为通过。这使“全部通过”成为假阳性。

### 2.2 Outline/schema 回归

执行涉及 outline source、LLM、long-arc、Progression 和 P0 integration 的测试时，结果为：

```text
1 failed, 54 passed, 6 warnings
```

失败项为 `tests/test_outline_sources.py::test_final_outline_validates_against_contract`。严格 schema 拒绝新增字段：

```text
Additional properties are not allowed
('genre_contract_version', 'genre_profile_id', 'progression_system' were unexpected)
```

这说明代码已经输出新字段，但契约 schema 尚未同步，属于发布阻断问题。

## 三、关键问题

### 3.1 Chapter 门禁尚未被真实证明有效

`runtime/chapter/finalizer.py` 虽然现在包含：

```python
if not genre_result.ok:
    raise GenreContractViolationError(genre_result)
```

但它加载 outline 的代码是：

```python
from ..outline.loader import load_outline
```

当前 `runtime/outline/` 中不存在 `loader.py`。异常随后被：

```python
except Exception:
    pass
```

吞掉，`declared_genre` 保持为“未知”。对“未知”题材，契约禁词表为空，因此违规正文不会被阻断。

实际复现：在临时项目中使用都市 outline 和正文“公司吸收灵气修炼，突破金丹境界”，`Finalizer.finalize()` 仍成功返回，没有抛出 `GenreContractViolationError`，且 `genre_profile_id` 为 `None`。

结论：chapter 门禁代码存在，但当前真实调用链仍可能失效，不能称为已验证的生产阻断。

### 3.2 Chapter 产物仍未携带题材标识

当前 3 个产物均为：

```json
{
  "genre_profile_id": null,
  "genre_contract_version": null
}
```

此外 `chapter-run`、run manifest 也出现同样的 null。原因包括：

- finalizer 无法正确加载 outline；
- `ChapterProductionOrchestrator` 在非 revision 分支重新构造 `ChapterFinal` 时，没有复制 `genre_profile_id` 和 `genre_contract_version`；
- 没有全链路一致性校验。

因此“ChapterFinal 已包含题材字段”只能算 schema 字段存在，不代表字段有效。

### 3.3 Progression 仍有兼容字段残留和语义混乱

`synthesize_final_outline()` 已能从 `progression_system` 读取 tiers，这是本轮有效修复。但它同时把这些 tiers 镜像到 `power_system`，并继续使用 `_build_conflict_ladder()` 这类 power 命名。

生成的都市 outline 实测包含：

- `progression_system.type = wealth`；
- `power_system` 同时存在；
- `world` 默认描述仍为周期性灾变、旧纪元真相、力量成长。

长弧产物 `LONGARC-001.json` 仍包含：

```json
{"axis": "power", "bands": ["初入行", "小有名气", ...]}
```

虽然部分代码能把都市 axis 改成 `wealth`，现有已落库长弧是旧产物，且未重新生成。这证明不能只看代码分支，必须重新生成并验收所有下游产物。

### 3.4 题材契约覆盖不足

`validate_outline_genre()` 仍只收集：

- logline；
- `world.summary`；
- 角色 arc/motivation。

它没有检查 `world.rules`、progression、冲突阶梯、first 30 chapters 等关键字段；`GENRE_REQUIRED_ELEMENTS` 仍只是定义，没有实际检查。

因此都市默认 world 中的“旧纪元、灾变、力量成长”可以绕过当前契约。简单禁词匹配也没有语境、否定、引用和复合题材处理。

### 3.5 测试报告与真实仓库不一致

工作报告宣称“38 个测试、无 warnings”，但当前测试文件中仍存在大量 `return True/False`，并能复现 38 个 warnings。部分端到端测试仍明确跳过真实 LLM：

```python
print("需要实际 LLM 调用，跳过")
return True
```

测试数量不能替代测试有效性。

### 3.6 产物数量与长篇能力不足

当前 `novel-dushi` 可见：

- `final-TASK-00001.json`
- `final-TASK-00002.json`
- `final-TASK-00003.json`

只有 3 个章节。长弧文件虽然规划到 100 章，但它是计划 artifact，不是 30+ 章真实生成证明。现有 3 个章节的质量审核结果还显示 `advance_to_next_chapter=false`、`trigger_revision_round=true`、`hold_for_human_review=true`，不能据此宣称连续生产稳定。

## 五、是否可以开长篇都市小说

### 当前允许

- 人工审核下生成 1–3 章原型；
- 修复前述问题后，再进行 5–10 章灰度试跑；
- 每章检查正文、题材契约、Progression、人物连续性和 chapter decision。

### 当前不允许

- 直接启动 30+ 章长篇自动生产；
- 将当前 `novel-dushi` 作为干净长篇基线；
- 依赖当前 chapter finalizer 自动阻断题材漂移；
- 将长弧规划文件视为长篇生成验收证据。

## 六、长篇生产前必须完成的整改

1. 修复 outline 加载：提供真实 `load_outline()`，或由 orchestrator 显式传入 outline/genre context，禁止吞掉加载异常。
2. 加入真实 chapter 违规测试：都市章节含“修炼/灵气/金丹”必须抛出门禁异常。
3. 修复 orchestrator 重建 `ChapterFinal` 时丢失题材字段的问题。
4. 同步 outline JSON schema，纳入 `genre_profile_id`、`genre_contract_version`、`progression_system`。
5. 将题材契约覆盖到 world rules、protagonist engine、progression、conflict ladder 和前 30 章。
6. 统一 `progression_system` 为主字段，旧 `power_system` 仅做读取兼容；重新生成 positioning、long-arc、import plan 和 chapter artifacts。
7. 完成至少 5 章真实生成，连续通过题材门禁和质量决策，再考虑 10 章灰度；30+ 章需另行验收。
8. 修复全部 pytest warning 和假阳性测试，确保失败测试以非零退出码暴露。

## 七、最终审核意见

本次改造相比初始版本有明显价值，建议保留以下成果：题材识别优化、题材分流 fallback、Progression 抽象、未知题材人工确认、outline 题材契约接入。

但当前不能批准以下结论：

- “38/38 无 warnings”；
- “Chapter 门禁已经真实阻断”；
- “全链路 genre_profile_id 已完成”；
- “Registry/长弧产物已完成一致性验证”；
- “可直接开长篇都市类型小说”；
- “达到优秀评级”。

最终建议：**保持 C+ / B- 评级，先修复门禁真实加载、schema、ChapterFinal 字段传递和测试假阳性，再进行 5–10 章灰度；目前不建议启动 30+ 章长篇都市生产。**
