# P1-03 最小可验证实验设计

**设计时间**: 2026-09-01  
**目标**: 用最小成本验证系统的商业潜力  
**原则**: 快速验证假设，避免过度投入

---

## 一、核心假设

基于前面的分析，需要验证的核心假设：

1. **假设1**: 生成的章节质量达到可发布水平
   - 当前证据：10章抽样8.1/10
   - 需要验证：人工编辑评价 + 真实读者反应

2. **假设2**: 评审系统改进后能区分质量
   - 当前证据：quality_center已实现471行
   - 需要验证：修复硬编码后实际使用

3. **假设3**: reader_sim的模拟有参考价值
   - 当前证据：已实现246行，12类persona
   - 需要验证：模拟vs真实数据的相关性

---

## 二、实验方案A：黄金3章人工盲评（推荐）

### 目标
验证假设1：生成质量是否达到发布水平

### 设计

**样本**：前3章（开篇最关键）

**三个版本**：
- 版本A：原始生成
- 版本B：自动修订后（如果有hygiene loop）
- 版本C：真人编辑修订（人工基准）

**评审者**：2-3名网文编辑或资深读者

**评价维度**：
1. 开篇吸引力（1-10分）
2. 情节合理性（1-10分）
3. 人物个性（1-10分）
4. 语言流畅度（1-10分）
5. AI味明显程度（1-10分，越低越好）
6. 继续阅读意愿（是/否）
7. 是否达到发布水平（是/否/需修改）

**盲评流程**：
1. 三个版本随机编号（不标注来源）
2. 每位评审者独立评分
3. 收集评分后汇总分析

### 成本估算

- 人力：2-3人 × 2小时 = 4-6人时
- 时间：3天（招募 + 评审 + 分析）
- 金钱：¥0-500（取决于是否付费）

### 验收标准

**通过**：
- 版本A或B在"达到发布水平"上≥2/3评审者认可
- 继续阅读意愿≥80%
- AI味程度≤5/10

**不通过**：
- "需修改"意见>50%
- 继续阅读意愿<50%
- AI味程度>7/10

## 三、实验方案B：10章小规模发布（理想）

### 目标
验证假设1+3：质量可发布 + 获取真实数据

### 设计

**平台选择**：选择1个门槛较低的平台
- 推荐：七猫小说（门槛低，数据反馈快）
- 备选：番茄小说、掌阅

**发布规模**：前10章

**监控指标**：
1. **曝光数据**：展现量、点击率
2. **阅读数据**：完读率、平均阅读时长
3. **留存数据**：1章→3章→10章留存率
4. **互动数据**：收藏、评论、打赏
5. **质量反馈**：评论内容、差评原因

**时间周期**：2周
- 第1周：前5章，观察数据
- 第2周：后5章，对比趋势

### 成本估算

- 时间：2周（发布 + 数据积累）
- 人力：整理数据1人×2天
- 风险：如果质量差可能影响后续发布

### 验收标准

**通过**：
- 3章留存率≥50%（行业平均约40-60%）
- 10章留存率≥30%
- 评论正面率≥60%
- 收藏/点击比≥5%

**不通过**：
- 3章留存率<30%
- 评论负面集中在质量问题
- 完读率<40%

## 四、实验方案C：A/B对比实验（进阶）

### 目标
验证假设2：质量评审改进的效果

### 前置条件
- 方案A或B已通过
- quality_center已接入

### 设计

**对比组**：
- 组A：ChapterReviewer（固定分数）
- 组B：LLMQualityJudge（18维度）

**生成**：
- 各生成10章
- 相同的大纲和设定

**评价**：
1. 人工盲评（2-3名编辑）
2. 质量维度分数对比
3. 章节间一致性

### 成本估算

- 生成成本：20章 × ¥0.1 = ¥2
- 评审成本：2人 × 3小时 = 6人时
- 时间：1周

### 验收标准

**质量提升**：
- 组B平均分>组A至少1分（10分制）
- 组B章节质量方差更小（更一致）
- 组B的"需修改"率更低

**成本可控**：
- 每章LLM成本<¥1
- 生成时间增加<30%

## 五、实验方案D：reader_sim校准实验（高级）

### 目标
验证假设3：模拟与真实的相关性

### 前置条件
- 方案B已完成，有真实数据
- reader_sim已修复

### 设计

**步骤1**：用reader_sim模拟前10章
- 记录12类persona的反应
- 记录模拟的continue_probability

**步骤2**：收集真实数据
- 章节级留存率
- 评论情感分析

**步骤3**：相关性分析
```python
# 示例分析
模拟：老白 continue_prob=0.7，小白=0.8
真实：完读率=0.75，3章留存=0.65

相关性：Pearson r=0.82（高相关）
偏差：模拟平均+5%（偏乐观）
```

### 成本估算

- 数据分析：1人×2天
- 统计工具：Python/R（免费）

### 验收标准

**可用**：
- 相关系数r>0.6（中等相关）
- 系统性偏差可识别（如+5%）
- 可通过调整修正

**不可用**：
- 相关系数r<0.3（弱相关）
- 偏差无规律
- 不同persona预测相互矛盾

## 七、风险控制

### 风险1：方案A不通过

**可能原因**：
- 生成质量确实不达标
- AI味太明显
- 情节不合理

**应对措施**：
1. 分析具体问题（哪些维度低分）
2. 针对性改进：
   - AI味高 → 启用hygiene loop
   - 情节问题 → 检查outline和IR
   - 语言问题 → 调整prompt
3. 重新测试

**是否继续发布**：❌ 不建议，先改进

---

### 风险2：方案B数据差

**可能原因**：
- 平台流量问题
- 题材不适合平台
- 质量问题

**应对措施**：
1. 区分问题来源：
   - 曝光低 → 平台/推荐问题
   - 点击低 → 标题/简介问题
   - 留存低 → 质量问题
2. 针对性改进
3. 考虑换平台或调整题材

**是否继续**：视具体指标
- 3章留存>40% → 继续
- 3章留存<30% → 暂停分析

---

### 风险3：reader_sim与真实不相关

**可能原因**：
- LLM模拟不准确
- Persona定义有偏差
- 样本量不足

**应对措施**：
1. 不影响核心功能（对比选优仍可用）
2. 调整persona描述
3. 或放弃绝对预测，只用相对对比

**是否继续**：✅ 可以，对比功能仍有价值

## 九、总结与建议

```

   ↓ 通过
第2-3周：10章小规模发布（方案B）
```

- 通过 → 继续方案B

- 3章留存>50% → 扩大发布

- 数据稳定 + 成本可控 → 扩大到50-100章
- 数据波动大 → 继续优化
- 质量下降 → 回到Phase 1
