7. 新发现的最大问题：PREPARE 可以绕过整个 Diff Enforcement

这是本轮最重要的发现。

当前 bind_change_review()：

if action == 'PREPARE' and not requested:
    return

这是有意设计：

PREPARE 可以在 scope 尚未冻结时调查。

这个原则本身没问题。

问题在于：

task_execution.py run

在 PREPARE 下仍然允许执行任意 child command。

例如理论上：

task_execution.py run \
  --task V2-004 \
  --action PREPARE \
  --output dist/prepare.json \
  -- python malicious_write.py

只要 child exit=0：

PREPARE
没有 change_review
没有 pre/post diff review

当前 task_entry.py 就可能：

status = PASS

。

换句话说：

IMPLEMENT
→ 强制 Diff Gate

但把同一条写代码命令改名：

PREPARE
→ 可以绕过 Diff Gate

。

而现行协议明确写：

PREPARE 不能被用来给接口实现、付费调用或正式认证改名。

所以这不是“规范没要求”，而是：

Normative rule
≠
actual enforcement

。

9. PREPARE 最合适的修法不是做 shell 命令白名单

我不建议：

只允许 cat
只允许 grep
只允许 git status

。

因为以后准备工作可能合法需要：

pytest --collect-only
schema validation
read-only probes
生成 dist 报告

维护 allowlist 很容易失控。

更稳的做法：

PREPARE 可以无冻结 scope，但必须是 repository-read-only

执行前：

before = observe(repository)

执行后：

after = observe(repository)

对于 Git-visible source/index/HEAD：

after != before
→ FAIL

。

允许变化的只有：

dist/

这类已经 Git ignored、不进入 observe() 的运行输出。

于是：

PREPARE
→ 可以调查
→ 可以跑测试
→ 可以写 dist 报告
→ 不能改源码
→ 不能 git add
→ 不能 commit
→ 不能改 packet

。

这样正好吻合协议。

至少增加攻击测试：

PREPARE + child modifies source
→ child may run
→ official result FAIL
→ cannot resume as PASS

最好进一步在可行的 sandbox/worktree 中跑 PREPARE，使副作用可丢弃，但那可以留到 V2-004。
