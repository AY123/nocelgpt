审核日期：2026-09-21（Asia/Shanghai）  
审核对象：当前工作区 `plan/` v1.1.0，而非 Git 已提交版本或旧版压缩包。  
报告性质：实施前架构与执行治理审核；未修改被审规划，未实施业务系统。  
核心证据：[反例运行结果](governance-probe-results.json)、[复现脚本](probe_plan_governance.py)、[问题登记](audit-findings.json)。

## 1. 审核结论

**可以开始 P0 仓库建设，但当前规划验证器不足以独立支撑任务、阶段和认证的可信关闭。修复本报告列出的治理缺口，并取得真实 P0 工程证据后，才能进入 P1。**

架构主方向成立：题材无关的 Narrative Core、唯一 Canon 提交边界、可注册的 Genre 扩展、合约与上下文编译、受控模型调用、章级生产、有限修复、分阶段认证，能够形成一条可检验的实施路线。双 Anchor 的差异也适合暴露题材耦合。

本次最重要的新发现是：**文字规范要求的约束，比现有规划验证器真正执行的约束更强。** 原有校验通过、32 项自测全部通过，但在独立临时副本中构造的 10 个应拒绝状态仍被接受，包括删除所有 CI 门禁、用不存在的证据声明测试或阶段完成，以及将 10 章里程碑缩减为一个仓库搭建任务。它们归并为 **5 类已复现的治理缺陷**，不能表述为 10 个独立生产漏洞。

此外有 **6 项实施前契约或产品决策细化要求**。这些来自文档交叉审阅，尚未在业务代码中验证，也不应被描述为已经发生的运行故障。

对“自动写出起点中文网爆款网文”的判断：目前规划为“可靠生产可供读者评估的中文网文”建立了较好的工程路径，但尚无证据证明作品具备稳定的阅读吸引力、较低人工依赖或市场竞争力。爆款属于外部结果，不能由章数、模型评分或工程 PASS 推导。项目应追求提高可验证的创作与运营能力，并保留不成功的结果。

## 3. 应保留的架构决策

### 3.1 Narrative 与 Genre 的分工是正确的

[领域与 Canon 规范](../plan/03_DOMAIN_CANON_AND_ARTIFACT_CONTRACTS.md)将世界事实、角色信念、角色知识、读者已知与作者计划分开，避免抽取器把“某人声称破产”直接提交成世界事实。Core 不带修为或公司财务专用字段，有助于控制题材耦合。

两个 Anchor 可以检验“同一个内核服务明显不同世界规则”的能力。不过它们通过认证只能支持这些版本和样本范围；不能外推到历史、悬疑、言情、同人或全部中文网文。后续扩充 Genre 应复用认证方法，而非复制一套生产内核。

### 3.2 Canon 不再只是可随意更新的背景资料

唯一写入口、稳定幂等身份、CAS、提交收据、事件与投影分离、保留历史证据、候选 overlay，都针对长篇生产中难以补救的状态污染。特别是“同键同载荷恢复原收据”和“章内失败不提前写 Canon”，应作为不可弱化的测试约束。

根提交、规范化哈希、短事务、证据保留等问题已交给 ADR-005/006，且最晚决策点设在首次持久化前。这是合理的渐进细化，不应因 ADR 尚未写完而重新判定整体架构失败。

### 3.3 从计划到正文有可追踪的消费关系

合约绑定 parent、Pack 和政策；上下文必需集合优先；正文接续采用上一接受章节的真实末段；人工修改产生新候选并使旧检查失效。这些改进比继续堆叠 Prompt 或更多 Agent 更接近 V1 暴露的问题。

必须保持“合法错误信念、回忆、隐喻、安静章节”可通过，避免把故事写成机械完成字段和爽点数量的流程。

### 3.4 先可靠内核，再高级智能的次序值得保留

模块化单体、PostgreSQL、有限任务规模，以及延后微服务、Kafka、Kubernetes、Agent Swarm、30+ GenrePack 的范围控制适合当前阶段。暂未有证据表明增加部署复杂度会解决本次问题。

P6 可做带隔离测试门禁的闭环接缝，P7 再完成正式 Q0–Q3 与 Permit；现行 M4 已纠正到 P7，不能把旧资料中的早期编号再次当作现行循环依赖。

### 3.5 认证已开始接近真实产品证据

[认证规范](../plan/06_CERTIFICATION_AND_PRODUCT_EVALUATION.md)明确记录失败分母、成本、人工介入、真实模型指纹、盲评、简单生成基线和 holdout。也允许“不优于基线”和“证据不足”，这是必要约束。

缺口主要在可执行协议与结果如何影响下一阶段，而非完全缺失产品评价。P8/P9 已安排早期真人阅读，无需把整套 P11 学习平台提前。

### 3.6 外部经验已进入实施映射，但效果尚待证明

[外部经验登记](../plan/machine/external-practice-register.yaml)及验证器已要求来源、限制、本地适配、任务与场景双向关联。正文接续、人物意图、上下文解释、恢复、人工改稿和修复停滞等经验已进入既有任务。

应保留这种“学习机制、独立适配、用本地证据评估”的方式。现在不需要因为外部项目更多而再扩架构。实际复用代码或提示词时，补齐不可变版本、具体文件和许可处理；本次没有将来源页面的宣传视为本项目收益。

## 5. 已复现的治理缺陷

### DA-01：检查“列出的门禁不能失败”，没有检查“必需门禁必须存在”

**证据。** `plan/scripts/validate_plan.py:253–255` 遍历当前 `gates`，检查 `allow_failure` 与合法阶段；没有冻结必要 ID 集合及最晚启用阶段。`PROBE-01` 将集合清空、`PROBE-02` 把全部启用阶段改为 P14，重新生成视图后均得到 PASS。相反，控制组将一个现存门禁改为 `allow_failure: true` 会正确被拒绝。

**冲突。** `07_PLATFORM_SECURITY_AND_DELIVERY.md:11–15` 和 `machine/ci-gates.yaml` 已明确 P0 的基础检查、P2 的 Canon 检查、P7 的确定性闭环等要求。缺陷在执行约束，不在缺少规范。

**影响。** 以后可以在不触发校验错误的情况下删除 CI 要求，或把本期应运行的检查延后。这不证明远程 CI 已绕过，但使本地计划的绿色失去关键含义。

**最小修复。** 为必需门禁建立受控基线和每阶段适用集合，验证 ID 唯一、必要项存在、启用阶段不晚于批准值；G-Pn 聚合当前适用门禁的真实结果。合法调整通过明确基线变更记录，而非禁止所有演进。

**验收。** 删除、重名、后移启用阶段、标记适用项 NOT_APPLICABLE 均需被拒绝；合法未来项可保持未启用；真失败必须阻断阶段关闭。

### DA-02：证据“有字符串”与“足以支持结论”之间缺少校验

**证据。** `validate_plan.py:148、166、229` 等只要求引用非空；`293–324` 的本地引用遍历未覆盖套件执行证据、阶段/里程碑证据、ADR verification refs 和 entry evidence。`PROBE-03` 用不存在文件声明套件 VERIFIED，`PROBE-06` 用不存在文件声明 P0 VERIFIED，都被接受。

更强的 `PROBE-07` 为 P0 四任务填入同一个 README，分别充当代码、测试、CI、验收证据，以 `SYNTHETIC-NOT-A-COMMIT` 作为统一 revision，拿 `templates/ADR.md` 这个仍为 PROPOSED 的模板支撑 ADR ACCEPTED。校验仍 PASS。它只证明本地证据语义未受到约束，**不是实际完成了 P0**。

**冲突。** `09_TASK_EXECUTION_GUIDE.md:17–25` 要求可定位的四类同变更证据与正式验收；P0 执行文档要求当前提交的可读 CI 记录。模板自身也明确不是完成证据。

**影响。** 任务和阶段可以形成彼此引用、自洽但没有真实实现依据的完成链。Manifest 只能证明被记录的字节一致，不能证明“这些字节足以证明完成”。

**最小修复。** 引入最小验收记录 Schema：记录种类、所属任务/检查、版本或变更身份、结果、执行环境、证据文件与内容 hash、裁决者、适用规则。先核验本地文件存在且为文件、可解析、不是模板，再核验所属关系、版本一致性、结论和覆盖。CI 使用实际 run/job 标识与可追溯归档，不允许由任意字符串自证。远程真实性和保留政策可以由受控 CI 接入与审核承担，不能靠正则看起来像 SHA 就宣布可信。

**验收。** 不存在文件、目录当文件、README 冒充运行报告、PROPOSED 模板冒充 ACCEPTED ADR、错任务、错 revision、过期或失败报告均拒绝。真实合格记录能通过。避免为“让脚本绿”创建空业务文件。

### DA-03：里程碑的最低内容可以被改写掉

**证据。** `validate_plan.py:239–252` 检查里程碑编号、列出的任务和状态，只对 M4 有一条特定约束。`PROBE-05` 将 M6 的必要任务改为只有 V2-001，并用合成证据关闭该任务后，M6 VERIFIED 可被接受；P8 此时没有通过。

**冲突。** `06_CERTIFICATION_AND_PRODUCT_EVALUATION.md:23–25` 要求双题材 10 章、故障注入与检查能力的证据汇合，现有 M6 清单也包含这些任务。

**影响。** “10 章认证完成”标签可能脱离认证内容，仪表盘和后续执行者会得到相互矛盾的信息。当前前置 Phase Gate 仍可能阻止部分后续任务，因此不能夸大为已证明所有阶段都能越过。

**最小修复。** 固定每个里程碑的最低义务与必要证据类型，显式建模里程碑、阶段和套件之间的聚合关系。M6 的必要项减少必须走基线修订。聚合关系要保持有向无环，不让阶段和里程碑互相等待。

**验收。** M6/M7 任一必要组成缺失、只凭低阶段任务完成、必要报告为 INCOMPLETE 时不得 VERIFIED。保留 V2-034/035 先完成运行报告、V2-036 后汇总的现有合理流程。

### DA-04：任务启动和 ADR 要求尚非完整可执行状态机

**证据。** `PROBE-04` 删除 V2-001 的 `required_decisions` 后，即使 ADR-001 仍 REQUIRED，也能标 IMPLEMENTED；这是单向关联检查的结果。`PROBE-08` 在合成 G-P0 通过后让 readiness 仍 PLANNED 的 V2-005 进入 IN_PROGRESS；`PROBE-10` 将 P0 entry gate 明确改成 BLOCKED，V2-001 仍可启动。均 PASS。

`validate_plan.py:95–104` 检查部分依赖/非 P0 阶段准入，`114–119` 只遍历任务当前保留的 ADR 列表，未检验 ADR 登记对任务要求的反向完整性。

**冲突。** `09_TASK_EXECUTION_GUIDE.md:5` 要求先细化再开始；ADR 登记有最晚决策任务及 timing。

**最小修复。** 增加 task↔ADR 双向完整性、readiness 准入和明确 entry gate 状态。将 `before_interface_implementation` 与 `before_live_call` 的实际约束落实到相应动作；不必禁止任务开始后做 ADR 准备，但不能允许先实现接口再补决定。单次快照不足以证明历史状态转移，若要验证转移顺序，应比较批准基线或保留变更记录。

**验收。** 三个复现反例拒绝；允许尚未到期的 ADR 保持 REQUIRED；允许合法重开并保留历史证据。不要把所有后期 ADR 都变成 P0 开工门槛。

### DA-05：任务关闭没有强制记录未关闭问题如何处置

**证据。** `PROBE-09` 在相关整改条目仍 OPEN_TRACKED、没有逐项处置记录时，使用合成材料关闭 V2-002，校验接受。`validate_plan.py:120–121、230–235` 主要验证关联存在和 finding 自身关闭字段；[验收模板](../plan/templates/TASK_ACCEPTANCE_RECORD.yaml)有一般性限制字段，没有可校验的逐项 finding disposition。

**冲突。** `09_TASK_EXECUTION_GUIDE.md:17` 明确 CLOSED 包括未关闭缺陷的明确处置。

**影响。** 同一问题跨多个任务负责时，每个任务都可能声称已完成，却无人说明剩余义务。仅登记 `ADAPT_OR_REJECT` 这类计划处置意向，不等于本次验收已说明做了什么。

**最小修复。** 验收记录列明 finding ID、本任务负责部分、已验证证据、未完成部分、后续任务/负责人/门禁以及结论。允许跨阶段问题部分完成，不要求每个关联任务都关闭整个 finding；没有明确剩余责任不能 CLOSED。

**验收。** 缺失处置被拒绝；有证据的局部解决与明确后续责任可通过；不能通过把所有问题统一标记“以后处理”满足要求。

## 6. 需要在对应阶段细化的运行契约

### DA-06：取消必须与唯一提交边界明确串行化

**已有覆盖。** `05_PRODUCTION_CONTEXT_QUALITY_REPAIR.md:89` 及 AT-V2-027-02 要求取消后迟到结果不得自动接受，人工改稿也会使旧证据失效。

**剩余边界。** `03_DOMAIN_CANON_AND_ARTIFACT_CONTRACTS.md:21–24` 的提交输入和 `05:63` 的 Permit 绑定没有明确说明：已签发 Permit 后请求取消，旧 Worker 或迟到调用直接到达 CanonCommitService 时，谁判断其执行权限已经撤销，以及这个判断如何与 CAS 原子生效。

仅在 UI/Workflow 层“丢弃迟到模型响应”不能覆盖已进入提交路径的工作。实现者可能在“取消只是意图”和“取消成功保证不再提交”之间采用不同语义。这是设计歧义，尚非已验证缺陷。

**建议。** 在 ADR-006 的提交边界和 ADR-010/011 的执行授权中明确 request/control revision 或等价 fencing 机制。有效取消与提交只能有一个先获得可观察的最终次序：取消先成功则旧执行不能产生新提交；提交先成功则取消不能假装回滚已经接受的章节，仍须返回原收据。正在取消时不得提前显示保证性成功。

同时区分恢复同一提交操作、生成新的候选修订和已接受章节的 Retcon；保持“同幂等键异提交载荷冲突”而不妨碍合法的提交前修复。

**必须有的并发测试。** Permit 已发出后取消再投递；取消与提交并发的两个获胜次序；重启后旧执行权限；提交响应丢失后取消仍能查回原收据；新版本操作不复活旧许可。V2-010 提前保留接口，V2-026/027 做正式集成，不等 P8 才第一次发现接口不支持。

### DA-07：不能用一句“有验证依据”代替语义裁决协议

**已有覆盖。** Q0–Q3、模型 provenance、UNKNOWN、正文/Delta 覆盖以及不可用平均分抵消硬失败，均已写入 `05:48–57`。无需再发明另一套 Quality Stack。

**剩余问题。** 哪些观察足以支持某个语义检查 PASS，模型置信高但证据不全如何处置，两个检查意见冲突如何合并，人工能否对某一语义事实作出裁决，当前仍需 ADR-011 给出可执行答案。只验证“有 provenance 和 confidence 字段”仍无法形成硬门禁。

**建议。** 为每一类检查定义：检查命题、适用范围、证据需求、PASS/FAIL/UNKNOWN/ERROR 条件、抽取覆盖要求和授权裁决边界。确定性 Schema/范围检查与概率性的语义判断分开计量。模型自报置信度不能等同经校准的正确率，也不能把“另一个模型同意”当成自动真值。

已知正文出现非法超自然事实但 Delta 刻意遗漏；引用小说台词与真实发生修炼；角色误信与世界事实；正文位置不匹配；相互矛盾或缺失证据，都应作为明确测试输入。人工可形成有范围、有版本的裁决记录，但不能改写既定硬失败或跳过必跑检查。

**边界。** P7 只需能够实施和验证的最小规则与样本，完整校准平台仍在 P11。规则可能误报或漏报，认证应报告覆盖与误差，而不是宣称语义零错误。

### DA-08：预算需要约束调用行为，不能只检查“填了预算”

**已有覆盖。** `05:19–25`、`07:31` 及 ADR-010 正确处理 UNKNOWN、待核费用和总上限；AT-V2-019-04 要求无预算不调用。

**剩余边界。** 有预算字段但余额不足、多个 attempt 竞争同一余额、超时已可能计费、重启后额度恢复、fallback 和 Repair 共享上限，这些没有落成明确的计划验收。记录费用不等于防止继续扩大支出。

**建议。** 真实调用前有预算准入与保守预留，UNKNOWN 保留待核责任；结算、释放与重试去重；重启恢复预算账本；Gateway、修复与工作流受共同上限约束。若首期保证完全串行，也应写明执行互斥和 UNKNOWN 待核上限，不必为了一个未来并发场景搭建复杂计费平台。

**验收。** 已耗尽余额、同时争用最后额度、超时后重试、重启、模型切换、修复循环都不能无限增大调用。预算保证应明确适用的计价版本、token 上限和误差政策，不能承诺无法控制的 Provider 最终账单精确封顶。

## 7. 面向中文网文与最终目标的认证细化

### DA-09：章数之外，必须冻结篇幅、自动程度和分母

**已有覆盖。** `06:5、12、17、35、53` 已要求章数不等于质量、失败分母、人工与成本、冻结目标篇幅和协议；本问题不是缺失这些理念。

**剩余缺口。** [认证模板](../plan/templates/CHAPTER_CERTIFICATION_RECORD.yaml)尚未明确协议版本、目标/实际篇幅、中文计数口径、人工介入分类和自动完成程度如何支持最终判定。通用引用可以链接这些信息，但目前没有可校验协议定义；ADR-013 应把这一义务写实。

建议协议至少包含：

| 维度 | 应冻结/记录的内容 | 避免的错误结论 |
|---|---|---|
| 运行规模 | 每题材书数、连续章数、目标及实际篇幅分布、总接受正文规模 | 短段落拼成 30 个编号就称长篇稳定 |
| 中文长度 | 字符/标点/空白/数字/拉丁文本的计数规则，另记模型 token | 用 token 冒充中文篇幅，或混用不同统计口径 |
| 自动程度 | 全自动、有限人工裁决、人工改稿分别计数；人工分钟与改写量 | 人工重写合格文本后仍声称自动成功 |
| 失败分母 | 所有开书/章节/候选尝试、放弃和重启；避免只选成功书 | 挑最好一次展示为稳定性 |
| 题材检测 | 自然污染与注入污染、误报漏报、UNKNOWN；语境分类 | 关键词零命中就称不串题材 |
| 阅读效果 | 盲评协议、读者匹配、弃读原因、继续阅读意愿和证据局限 | 工程收据链直接推导可读性 |
| 成本/效率 | 总调用、待核费用、接受章成本、人工时间、总耗时 | 只报一次 Writer 调用价格 |
| 版本与停止 | 协议/hash、输入/模型/策略、预算上限、失败/中止条件 | 看完结果改门槛或换版本继承旧 PASS |

无需现在随意填一个全题材通用字数或读者阈值。先按实际认证目的选取代表性目标，再在运行前冻结；长度规则是评测口径，不应成为机械干预文学表达的唯一硬门禁。

### 8.1 “都市写成玄幻”需要分层证明

题材错误可能来自错误 Pack 绑定、Context 注入、生成文本越界、抽取遗漏、质量误判或旧证据复用。只在 Prompt 写“禁止修炼”，或者在数据库不设置 cultivation 字段，都不能证明消除污染。

需要保留的闭环为：输入绑定正确 → 世界扩展类型正确 → 正文语境与 Delta 一致 → 违规正文不能漏过检查 → UNKNOWN 不伪 PASS → Permit 绑定当前候选 → 提交时再核验。自然生成和故意注入样本都要有；合法的游戏、梦境、引用、比喻和误信须避免被简单关键词规则拒绝。

即使这些检查通过，也只说明所用样本与规则覆盖下的效果。两个 Anchor 的认证是扩展机制成立的重要证据，不能证明对所有未来题材普遍无误。

### 8.2 “自动写出好网文”还需要什么证据

| 用户目标 | 当前路线中的对应能力 | 尚需获得的证据 |
|---|---|---|
| 自动写作 | P5～P7 生产与修复 | 没有人类代写的真实运行、人工接管率、停止边界 |
| 中文网文特征 | Genre + 计划 + 阅读评价 | 人物选择、因果、承诺兑现、章节接续、持续阅读体验的正文证据 |
| 长篇稳定 | P8/P9/P12/P14 | 每个规模独立运行与恢复证据，不能只线性外推 |
| 有市场竞争力 | P8/P9 读稿，P11 校准，P13 市场 | 可比条件下的阅读反馈、实际需求与投入回报 |
| 爆款 | 外部读者与市场结果 | 当前无法保证，也不能由技术认证代替 |

早期可以评估人工审稿者是否愿意继续读、在哪里弃读、人物选择是否可信。真实市场受众和发行反馈仍到 P13。这样既不延后所有产品验证，也不让复杂市场分析抢占稳定内核。

### 10.3 应避免的整改方式

- 不为通过路径校验创建空测试、虚假 CI URL 或空验收文件。
- 不把 64 个跨阶段 finding 一次性标 CLOSED；本任务负责部分必须有实际证据。
- 不把所有 ADR 强行提前到 P0，也不使用 REQUIRED 状态作为无限期拖延接口决定的理由。
- 不把证据校验扩张为新的大型平台；先实现本期足以拒绝已知反例的规则。
- 不以增加模块数、Agent 数或研究篇数代替真实章节试验。
- 不为提升通过率删除失败分母、减小必要检查集或降低既定硬门禁。
