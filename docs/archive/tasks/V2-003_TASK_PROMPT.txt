## 5. Architecture Fitness 的可观察边界

优先使用确定性 Python AST/import graph，不执行候选源码，不用 LLM 意见充当硬门禁。
- 自动扫描真实 src/anovel 下全部 Python 源文件，记录模块、文件/hash、import edges 与扫描数量。生产骨架和 synthetic fixture 的覆盖分别报告。
- domain 不依赖 Provider SDK、数据库实现、gateway/workflow/web/基础设施实现；结合内部依赖关系检查包装转引。记录允许的标准库/边界依赖以及未知依赖的处理。
- 正确处理绝对/相对 import、alias、可解析 re-export 和动态导入。不能确定的加载行为明确拒绝或标为需审查，不静默当安全。
- 区分 Canon 公开提交服务与内部持久化写能力。合法 Workflow 请求公开提交接口要有正例；Writer/Reviewer/Reference 等未授权获取内部写能力要有负例。导入矩阵是可审查的静态规则，不声称证明运行时 Canon 所有权或 DB 权限。
- 生产代码不能导入 archive/测试 fixture；加载路径、符号链接和动态加载旁路须明确处理。
- 适用硬门禁不能被生产配置/开关禁用；规则记录启用阶段。尚未到期的 P2 权限与 V2-004 可信 CI 不冒称已实施。

当前尚无业务模块的规则用 tests/architecture 下无副作用 synthetic package 验证，不提前创建 CanonCommitService、数据库、CAS、Event Store 或整套空业务目录。

## 6. 实际差异、基线与路径

比较固定开工 Git revision、开工 index/worktree 身份与当前状态；不能只看 HEAD 到工作区、单独 git diff 或只解析 status 文本。读取真实内容，覆盖已提交任务改动、index、worktree、untracked、删除、模式/类型变化与重命名两端。

Git rename 是推断：记录 old/new/status；未识别的 rename 按 delete+add 分别检查。allowed_paths 只采用精确文件或以 / 结尾的受限目录；拒绝 traversal、绝对路径及符号链接逃逸，不跟随外部链接读取/修改内容。

普通范围内删除/重命名可按已有任务授权执行，无须另造逐文件审批门禁；测试、验收、保护规则删改仍进入防降标处置。路径通过不等于业务语义通过。新增依赖、跨阶段代码和支持性修改均要保留任务归属复核。

实际无差异可以报告 no changes；它不证明负例覆盖。若 Git/文件清单显示有差异但检查集合为空或漏项，必须失败。

固定比较基线、允许范围及例外输入，候选改动不能通过同时改 packet/白名单/baseline 自行获得放行。新增 untracked 同样检查，不能因尚未 git add 而跳过。新增 ignore/exclude 也属于保护变化，不能藏掉被审源码。

## 7. 防降标与合法修订

结构化比较 machine YAML、测试 AST、工具配置与保护源码。至少测试：删除 AC+scenario+对应测试、删除测试函数/文件、pytest/unittest skip/skipif/xfail（含可解析别名）、降低 threshold、扩大 exclude、引入 allow_failure、删除 Gate/check、修改最低基线、修改 checker 与其 fixture/范围规则。

不能自动证明的测试语义变化应报告具体旧/新差异供审查；不能声称一般程序等价性已被静态证明。格式重排、可证明的等效重构、增加测试/断言、规则增强提供合法正例。

疑似削弱或保护实现变化使用小型结构化变更记录，绑定 task、path、旧/新内容身份、原因、影响、受影响任务/场景/Gate、替代验证及可核对授权依据。授权来源须锚定已有用户授权或固定开工输入；候选中新增的 approved_by/current_agent、自填字符串或同步改 ref/hash 不能自证授权。范围/内容改变后须重新核对，不能用旧例外批准新改动。

本地检查证明差异与授权输入的一致性，不提供对抗同写权限者的安全边界。真正的受保护来源、执行权限和 CI 由 V2-004 建立，不为 V2-003 新建审批服务器、Agent 平台、守护进程或部署。
