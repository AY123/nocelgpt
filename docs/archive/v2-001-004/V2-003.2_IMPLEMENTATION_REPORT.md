### Phase B: F-001 - PREPARE Action Semantic Closure (P0)

**Commit:** af63cb74bde0a3ac9e1e5f5eaacb855f271af049

**Target Invariant:**
```
PREPARE SHALL NOT leave Git-visible persistent implementation changes
in repository-controlled state (HEAD/branch/index/tracked worktree).
```

**Root Cause:**
PREPARE was originally designed to allow read-only exploration before scope is frozen, but it could be misused to persist implementation changes that should only occur under IMPLEMENT action.

**Implementation:**

**File:** `plan/scripts/task_entry.py` (+22 lines, -1 line)

Added before/after repository state comparison:
```python
# Before command execution
if args.action == 'PREPARE':
    before_command = observe(root)

# Execute command
result = subprocess.run(command, ...)

# After command execution  
if args.action == 'PREPARE' and before_command is not None:
    after_command = observe(root)
    if (before_command['head'] != after_command['head'] or
        before_command['branch'] != after_command['branch'] or
        before_command['index_sha256'] != after_command['index_sha256'] or
        before_command['dirty'] != after_command['dirty'] or
        before_command['status_sha256'] != after_command['status_sha256']):
        errors.append('ENTRY_PREPARE_IMMUTABLE: ...')
        report['status'] = 'FAIL'
```

**Detection Coverage:**
- ✓ HEAD changes (commits)
- ✓ Branch changes
- ✓ Index modifications (staging)
- ✓ Tracked worktree changes
- ✓ New non-ignored files

**Allowed:**
- ✓ Git-ignored outputs (dist/, cache/, etc.)
- ✓ Read-only operations
- ✓ Test execution without mutations

**Enforcement:**
```
PREPARE + repository mutation → FAIL (ENTRY_PREPARE_IMMUTABLE)
IMPLEMENT + same mutation → normal flow (unaffected)
```

**Tests Added:**
- `test_prepare_immutability_check_exists`: Verifies gate code present
- `test_implement_action_unaffected_by_prepare_gate`: IMPLEMENT path preserved

**Adversarial Validation:**
The key test proves action semantic boundary: even a legal in-scope change that would pass under IMPLEMENT is rejected under PREPARE, confirming **PREPARE ≠ IMPLEMENT**.

### Phase C: F-002 - Collection-Control Authorization Closure (P1)

**Commit:** af63cb74bde0a3ac9e1e5f5eaacb855f271af049 (same as F-001)

**Target Invariant:**
```
Test collection/discovery control changes SHALL NOT be approved by
same-AI self-review using only generic task authorization.
```

**Root Cause:**
`TEST_COLLECTION_CONTROL` findings had `severity_kind = 'REVIEW'`, allowing same-AI self-approval via `REVIEWED_NO_WEAKENING` + generic task authorization.

**Implementation:**

**File:** `plan/scripts/weakening_checks.py` (+13 lines, -1 line)

Added collection control code category:
```python
# New constant
_COLLECTION_CONTROL_CODES = {
    'TEST_COLLECTION_CONTROL',
}

# Modified severity assignment
if code in _WEAKENING_CODES:
    severity_kind = 'WEAKENING'
elif code in _COLLECTION_CONTROL_CODES:
    severity_kind = 'AUTHORIZATION_REQUIRED'
else:
    severity_kind = 'REVIEW'
```

**Effect:**
- `TEST_COLLECTION_CONTROL` → `AUTHORIZATION_REQUIRED` (not `REVIEW`)
- Fixture-only conftest → `REVIEW` (unchanged)
- Same-AI self-review with generic auth → blocked

**Tests Added:**
- `test_collection_control_requires_authorization`: Verifies severity upgrade
- `test_fixture_only_conftest_remains_review_level`: No false positives
- `test_collection_control_codes_properly_categorized`: Code categorization
