## Executive Summary

V2-003.2-H1 successfully closed a content fingerprint boundary gap in the PREPARE immutability gate identified during independent code review.

**Issue:** PREPARE gate compared Git status shape but not actual file content identity.  
**Fix:** Compare `observe()['files']` field for true content identity enforcement.  
**Impact:** F-001 invariant now fully enforced with no adversarial bypasses.

---

## Root Cause Analysis

### Original Implementation (V2-003.2)

```python
# Compared status shape, not content identity
if (before_command['dirty'] != after_command['dirty'] or
    before_command['status_sha256'] != after_command['status_sha256']):
    # FAIL
```

### Boundary Gap

**Attack Scenario 1: Already-dirty file**
```bash
# Before: plan/foo.py already modified (M)
# PREPARE: echo "more" >> plan/foo.py
# After: still shows "M plan/foo.py"
# Status shape: UNCHANGED
# Content SHA: CHANGED
# Original gate: PASS (false negative)
```

**Attack Scenario 2: Untracked file**
```bash
# Before: ?? untracked.txt exists
# PREPARE: echo "modified" > untracked.txt
# After: still shows "?? untracked.txt"
# Status shape: UNCHANGED
# Content SHA: CHANGED
# Original gate: PASS (false negative)
```

**Root Cause:**
- `dirty` boolean: only indicates presence of changes, not content identity
- `status_sha256`: hashes porcelain output format, not file contents
- Neither detects content changes when status shape is stable

---

## Fix Implementation

### Code Change

**File:** `plan/scripts/task_entry.py` (+7, -4)

```python
# Before (V2-003.2):
if (before_command['head'] != after_command['head'] or
    before_command['branch'] != after_command['branch'] or
    before_command['index_sha256'] != after_command['index_sha256'] or
    before_command['dirty'] != after_command['dirty'] or           # WEAK
    before_command['status_sha256'] != after_command['status_sha256']):  # WEAK
    errors.append('ENTRY_PREPARE_IMMUTABLE: ...')

# After (V2-003.2-H1):
if (before_command['head'] != after_command['head'] or
    before_command['branch'] != after_command['branch'] or
    before_command['index_sha256'] != after_command['index_sha256'] or
    before_command['files'] != after_command['files']):           # STRONG
    errors.append('ENTRY_PREPARE_IMMUTABLE: ...')
```

**Why `files` field is sufficient:**

`observe()['files']` already contains:
```python
{
    'path': 'plan/foo.py',
    'kind': 'tracked',
    'sha256': 'abc123...',  # Actual file content SHA
    'executable': False
}
```

Comparing `files` lists provides true content identity enforcement.
