1. 重建裁决
ANovel V2 采用 Greenfield Rewrite + Selective Migration。V1 被定义为“实验平台、证据库、失败样本库与算法思想库”，而不是 V2 的代码基底。代码可以重新组织；已经验证过的领域认知、测试样本和反模式必须保留。

4. 已确认的关键反模式
运行时出现小说专用硬编码（如固定主角名/固定 Bible 版本）会把“平台能力”降级成“单书脚本”。
提取失败返回 None、缺 Contract 跳过校验、连续性错误只 warning 但仍推进状态，都会形成 silent corruption。
契约集成默认关闭意味着安全系统并未成为生产默认路径。
placeholder hash 或过窄 run fingerprint 不能形成真正的 provenance/replay。
StageGraph 若只存在于测试/文档而不驱动真实执行，就属于“架构幻觉”。
大量生成物、实验报告、源码混在单仓会提高噪音和所有权不清风险。

7. 新仓库启动策略
冻结 V1：仅允许安全修复、证据归档，不继续新增大功能。
创建 V2 独立仓库与 architecture baseline；V1 通过只读引用作为证据源。
先迁测试夹具与领域规则，再迁任何实现。
第一批只做都市现实/商业与东方玄幻两个压力测试 Pack。
新代码必须满足 Module Ownership、Contract、State authority、failure semantics 四项审查。
8. V2 Architecture Guard
Guard
规则
No Novel-specific Runtime Constants
runtime 不允许出现项目角色名、固定地点、固定 Bible 版本
No Side-door Canon Writes
所有事实改变必须经过 ChangeSet + Commit Permit
No Parallel Production State
发布/修订/评审不得各自定义最终真值
No Silent Skip
关键依赖缺失必须 BLOCK，不允许“无契约，跳过验证”
No Agent Without State Contract
新增 Agent 前先说明 Domain/State/Input/Output/Failure
No Consumerless Schema
无真实消费者的 Schema 不进入 main
No Market Trend in Core
热点只存在版本化 Snapshot，不硬编码 Runtime

9. 迁移完成判据
当 V2 能使用迁移后的 V1 失败样本完成 Genre/Character/Timeline/Commit/Resume 回归认证，并在全新小说项目上连续 30 章零重大硬事实违规时，才认为“V1 的核心经验已被有效吸收”。
